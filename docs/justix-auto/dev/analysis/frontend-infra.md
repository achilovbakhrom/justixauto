## 1. Concrete frontend choice and ownership

Choose React + strict TypeScript + Vite client SPAs, npm workspaces, React Router declarative routes, TanStack Query for server state, React Hook Form + Zod for local forms. No SSR/public SEO requirement exists in the four confirmed workspaces; a full-stack React server would duplicate the Go boundary. These libraries are proposals, not inherited Gaze dependencies. React documents Vite and separately selected routing/data layers as a supported build-from-scratch approach, with additional framework responsibilities as the trade-off. [React guidance](https://react.dev/learn/build-a-react-app-from-scratch).

One root npm lockfile; proposed paths: `web/apps/{realization,financing,insurance,admin}/src/{app,routes,features}`; `web/packages/{ui,tokens,api,session,operations,test-kit}`. Preserve existing documentation tooling and root scripts. No shared package imports an app; apps never import each other. App-local `features/<domain>` owns view composition, not authoritative business state. Seven typed domain clients live in `web/packages/api/src/{identity,inventory,commerce,retail,financing,insurance,documents}`. Synthesis must merge this layout with the single-module Go layout once.

Each app independently builds to a static bundle; one edge origin serves `/`, `/finance/`, `/insurance/`, `/admin/` and `/api/v1`. Use matching router basename/build base; prefix-specific history fallback must never return HTML for `/api/*`, missing assets or another app. No microfrontend runtime, copied stock state, fifth app, retired role folder or Figma dependency.

Common tree: `AppProviders(QueryClient, SessionContext) → SessionBoundary → AppShell → RouteBoundary → FeaturePage`; `OverlayHost` and `OperationReceipt` are siblings inside the authenticated boundary. AppShell accepts app-specific navigation; Insurance's current distinct layout is preserved, not forcibly restyled into Realization. RouteBoundary owns loading/empty/unavailable states; FeaturePage owns existing business action placement.

Shared components: Button, Field/Error, CountryRegionFields, Modal/Dialog, ConfirmDialog, Table/Pagination, StatusBadge, Tabs, Toast/Alert, MoneyText, VehicleIdentity, VehiclePhotoGroups, CompanyBranchPicker, DocumentVersions, HistoryStepper and OperationReceipt. Domain forms and state transitions stay app/domain-local; sharing the document list does not grant document-review authority.

Use CSS Modules for feature styles and shared CSS custom properties; no new component theme. Extract from `common.css` and scoped overrides: canvas `#f6f7f9`, surface `#fff`, border `#d9dee7`, text `#18212f`, primary `#1769e0`, success `#147a55`, warning `#a85c00`, danger `#c23b43`, radius `6px`, default sidebar `232px`, topbar `64px`; preserve the responsive sidebar override `76px` only at its actual media condition. Font stack is `Inter,-apple-system,BlinkMacSystemFont,"Segoe UI",sans-serif`; don't assume a font binary exists. Extract remaining typography/spacing/responsive rules in a focused token task; do not invent dark mode. Existing SVG vehicle illustrations are references/assets, not generative replacements.

## 3. Exact client-facing contracts

Consume shared `/api/v1` conventions unchanged: writes use `Idempotency-Key: UUID`; existing aggregate changes use `If-Match: "<revision>"`; immutable decimal-string money and ISO dates; domain clients generated from reviewed OpenAPI DTOs plus runtime boundary validation. Reject invalid response shapes as transport failures, not empty success. Dates have explicit business timezone; no implicit browser-local schedule arithmetic or silent currency conversion.

Identity supplies `SessionView = {userId, contextRevision, activeCompanyId: UUID|null, branchScope:{mode:"ALL"|"SELECTED",branchIds:UUID[]}, permissions:string[], capabilities:string[], membershipCompanyIds:UUID[], mfaState}` and scoped context-change response. Endpoint names and final MFA discriminants belong to identity synthesis, not independent FE inventions. Global-role permission UI is advisory; backend independently evaluates company capability, membership/branch, party and object state on every command. No body companyId grants access.

Cookie transport uses `credentials:"same-origin"`; session cookie is server-set HttpOnly/Secure, with approved SameSite and CSRF token/origin checks from identity/edge. Never put session secrets/passwords/documents in localStorage, query strings, analytics or audit. Use a safe allowlisted return path at login. A session event/context change clears all old-scope views and dialogs; app-to-app navigation uses the same authenticated origin, not mock credentials. 401 purges sensitive caches and requires login; 403 keeps only currently authorized context, 404 discloses no cross-tenant existence. No finance/insurance impersonation by Admin.

Query key = `[app,userId,contextRevision,activeCompanyId,sortedBranchIds,domain,resource,id?,filters,cursor]`; do not use company ID alone. Context switch increments a local request epoch immediately, cancels queries, hides old data and pending forms, performs the server switch, then replaces QueryClient scope; discard late responses whose epoch/contextRevision differs. Cross-tab context notifications contain revision only and trigger session reload; API must reject stale context requests even before browser notification arrives. No persistent query cache for PII.

Technical cache proposal: detail/list `staleTime=15s`, refetch on focus/reconnect, read failures retry at most twice only for network/502/503/504; never retry 401/403/404/422. Mutations have automatic retry disabled. In-flight forms are snapshots, so background queries never overwrite dirty inputs. Query defaults include stale data and automatic retries, making explicit overrides necessary. [TanStack defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults).

`CommandReceipt<T> = {data:T,revision:number,operationId:UUID}`; `Accepted = {operationId:UUID,status:"pending"}`. GET `/api/v1/operations/{id}` returns `{operationId,status:"pending"|"succeeded"|"failed",result?:{href,revision},error?:ApiError}` with tenant/actor authorization; exact optional field naming is a synthesis contract. Receipt revision must never be overwritten by an older projection. Reads carry `asOf` and aggregate revision; show confirmed receipt until fetched revision reaches it. Invalidate affected scoped query keys after success, not all users/companies.

202 workflow: disable repeat submit; store operationId/idempotency key and command kind only (no business payload) in per-session recovery metadata; poll while visible at proposed 2s, backing off to 10s, resume on reconnect/focus. Pending is not failure after a time limit. Network failure before receipt enters unknown-outcome: retain same key/input in memory and query owner receipt or replay exactly the same command with the same key; never mint a new key on Retry. Reload recovery needs an authenticated owner receipt lookup by original key before exposing a new create action; synthesis must provide that backend boundary. Completed/failed operations remain reopenable as allowed by session scope. Logout/context switch clears local recovery metadata; server operation is not cancelled.

Form reducer: edit→validate→confirm when required→submit→receipt/pending; 422 maps safe `fields` to inputs without clearing draft; 428 is client-contract failure; 412 preserves draft and requires explicit fresh load/review/new submission; 409 preserves draft and explains invariant/idempotency conflict; 5xx/network preserves draft with unknown-outcome handling. Do not auto-merge revisions. Modal traps focus, restores entry focus, has labelled heading/error summary, and never interprets close/Escape/browser abort as durable cancellation. Pending operations can detach to receipt tracking; only an explicit supported cancellation command can request compensation.

Uploads use documents-service authorized intents, byte upload, finalize and scan status; business app attaches only a returned document/version ID it may access. Browser MIME/size checks are convenience; get approved limits from server config, not demo 1 MiB. Block business acceptance while upload/scan incomplete; interrupted bytes/rejected scan remain distinct from financier `changes` and `accepted`. Replace by a new version; preserve previous accepted/rejected history. Object-store URLs must be short-lived and authorized; don't render untrusted active content.

Multi-item forms consume an endpoint-declared atomic or partial-result contract. For partial result, require per-item stable ID/status/error and retry only failed items with explicit item idempotency semantics; no generic client splitting of an atomic warehouse receipt. Until this contract/state is confirmed, use atomic behavior only where backend declares it.

## 4. Infrastructure and dependency strategy

Retain Gaze technologies/shape: one Go module, separate command/projection binaries, private PostgreSQL ownership, GORM, Echo HTTP, RabbitMQ, Zap, OpenTelemetry; Redis only for explicitly non-authoritative ephemeral cache/rate limiting, not events/reservations. gRPC/protobuf only for approved internal ports; no WebSocket solely because Gaze has one. Use reviewed AMQP client adapter; prefer RabbitMQ-team `amqp091-go` over inherited streadway as an explicit dependency-change ADR, not a claimed Gaze feature. [Maintainer repository](https://github.com/rabbitmq/amqp091-go).

Local topology proposal: one PostgreSQL container with seven databases/users (one per owner); one RabbitMQ vhost with restricted service credentials; optional Redis; OTel collector + Jaeger development profile; private documents filesystem volume behind the documents service for local tests, storage port for later production object-store choice. No browser directly reaches broker/database. Private DB credentials and service scopes prevent accidental cross-domain SQL. Migration execution belongs to each owner; cross-service invariant tests use APIs/events, not shared SQL updates.

Proposed local host endpoints bind loopback: edge `8080`; Vite ports `5173..5176` for four apps; Postgres `55432`; RabbitMQ `5672`, management `15672`; Redis `56379`; Jaeger `16686`, collector `4317/4318`. Development edge proxies four Vite prefixes and `/api/v1`, preserving same-origin sessions. Service HTTP uses container-private `8080`; no host publication by default. These allocations are proposals, not observed available ports. Startup must fail clearly on collision rather than kill unrelated processes.

Select a maintained SQL migration CLI in lock ADR (recommend `golang-migrate/migrate`), SQL files under each service, migration ledger per database. Apply forward migrations in dev/test; production destructive rollback needs separate authorization. Service startup validates schema compatibility and readiness without auto-editing production schema. Outbox/inbox reliability is the coordinator's proposed ADR; Compose health alone cannot certify it.

Before scaffolding, a serialized dependency-lock task selects supported stable patch releases for Go/compiler images, Node/npm, frontend libraries, GORM/Echo/AMQP/gRPC/protobuf, database/broker/cache, migration CLI and telemetry components. Record official support/security evidence, compatibility matrix, licenses and date; pin direct dependencies exactly plus `go.sum`, npm lock, container digests and CI action SHAs. Do not inherit Go 1.23/Alpine3.12/RabbitMQ3.13.6/gRPC-dev/Jaeger-latest as supported. Verify selected Vite's Node requirement rather than upgrading/installing from an unchecked `latest` template. [Vite requirements](https://vite.dev/guide/).

Go module minimum >=1.23 remains the user's reference floor, not the production toolchain recommendation; `bash tools/go.sh` must validate the selected locked compiler after lock approval, not merely accept whichever installed compiler clears 1.23. Node22.23/npm10.9.8/Go1.24.2 observations are preflight facts, not compatibility certification. Toolchain changes are explicit prerequisite tasks. No installs/pulls were performed in this slice.

Proposed commands, not currently implemented: `npm run dev:<app>`, `npm run typecheck`, `npm run lint`, `npm run test:unit`, `npm run build:apps`, `npm run test:e2e`; `bash tools/go.sh test ./...`, `bash tools/go.sh test -race ./...`, `bash tools/go.sh vet ./...`; Make targets `infra-up`, `migrate`, `test-integration`, `dev`, `verify`. Keep existing `mocks:verify/test/serve` intact. No real customer data, production secrets or external partner calls in seeds/fixtures.

CI proposal: platform-neutral scripts, with GitHub Actions adapter only if approved hosting uses GitHub; first verify independent repo root + pinned toolchains, install from locks, typecheck/lint/unit/build, then isolated PostgreSQL/RabbitMQ integration and Playwright app contract smoke. Service jobs use unique DB/vhost names; readiness polls have bounds. Add replay/duplicate/stale/version-gap/poison/outbox crash tests, tenant isolation and reservation race tests, document access tests. Publish redacted test artifacts locally/CI only; no automatic deployment. Keep lockfile/migration registry owners serialized.

Tests: Vitest + React Testing Library for reducers/forms/components; MSW contract fixtures generated/validated against owner DTOs; Playwright for four-app paths and cross-app finance/insurance round trips. Screenshot comparisons use immutable current HTML at matching viewport, state, mock data and font availability; first capture hashes/versions and named states, then compare React. One browser-heavy QA at a time. The 106 mock tests are useful baseline examples, not Go/React acceptance. Run React Doctor after actual React changes under its skill, not during this documentation slice.
