## Scope and command contract

The root manifest discovers `web/packages/*` before `web/apps/*`. Each child is
an npm workspace with a unique package name and its own `package.json`. Keep
shared packages in dependency order when they eventually need compiled artifacts;
npm workspace iteration is declaration order, not a dependency graph scheduler.
Root `build:apps` selects children of `web/apps`; it does not build dependencies.
Run `build` for the full workspace build. No empty app or placeholder test is added.

Existing `mocks:*` and `doctor` script strings and the three direct mock-tool
versions are preserved. Root remains CommonJS because the reference `.cjs` tests
require existing `.js` modules. Future app/package manifests should declare
`"type": "module"` for their Vite/ESM source. Reference bundles remain immutable.

| Root command | Contract |
|---|---|
| `typecheck:config` | Strictly checks the shared Vitest config and dependency declarations, without `skipLibCheck` |
| `typecheck` | Checks shared config then invokes every child's required `typecheck` script |
| `lint` | Checks `web` with the shared flat config and zero allowed warnings; current scaffold checks configuration only |
| `test:unit` | Explicit shared config, supported runner loader, child `test.projects` discovery; absent projects or tests fail |
| `test:unit:coverage` | Same unit tests with the matching V8 coverage provider |
| `build` | Invokes every child's required `build` script |
| `build:apps` | Invokes the required `build` script of all app workspaces |

There is no `--if-present`, `--passWithNoTests`, fake e2e command, synthetic account,
browser persistence or invented business calculation. Missing workspace scripts
fail instead of silently skipping checks. Full typecheck/build/test commands
intentionally fail while no actual workspaces/tests exist.

## Child scaffold contract for subsequent tasks

Each child owns a `tsconfig.json` extending `../../tsconfig.base.json`, with
explicit includes for its source/tests and any local config requiring checking.
The base enables strict checking, unchecked-index protection, exact optional
properties, isolated/verbatim modules, no emit and no ambient types by default.
Browser workspaces add the approved React declarations when React is introduced;
Node configuration files need Node types and may use a separate checking command.
Do not disable library checking to conceal compatibility errors.

Required child scripts: `typecheck` runs `tsc --project tsconfig.json` (and checks
any separately scoped config); `build` typechecks before Vite or the package's
appropriate build step. Source-only packages may have a checking build with an
explicit documented source export contract; they must not claim generated output.

Each child with tests owns `vitest.config.ts` (or `.mts`) and exports `defineConfig`
from `vitest/config` with a unique `test.name`, explicit `test.environment`, and
`test.include` such as `src/**/*.test.{ts,tsx}`. Vitest roots that project at its
config directory. The shared root uses explicit project config globs; there is
no implicit `defineWorkspace` discovery. Add `setupFiles` for the shared test kit
only after that module/file exists; no missing setup import is preconfigured.
The root coverage scope is app/package source, excluding declarations and tests.
No production coverage threshold or application coverage success is claimed here.
