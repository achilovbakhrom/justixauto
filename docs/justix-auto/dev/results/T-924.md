The existing `/justixauto`, two durable topic exchanges, fourteen durable quorum
queues and fourteen bindings are retained. Each owner now has separate disabled
`relay_<owner>` and `intake_<owner>` identities. Relay can access only the
integration exchange and cannot read any queue. Intake reads only its own inbox;
it can write the quarantine exchange only when an explicit quarantine route is
activated. Intake has no integration publication or quarantine-read capability.
Projectors and redrive receive no implicit credentials or capabilities.

Existing `svc_<owner>` identities are deliberately retained with explicit deny
resource and topic grants, so importing this change replaces their former broad
permissions. Merely omitting those users from a definition import would leave
old permissions behind. All users have empty password hashes and no privileged
tags. Provisioning remains separate from runtime; no runtime can configure,
actively redeclare or bind topology, publish through the default exchange, or
read another owner's queues.

The checked-in activated integration and quarantine arrays are both explicitly
empty. Every topic write is the impossible regex `a^`, including empty routing
keys. This avoids interpreting `^$` as deny-all for a topic key, where the empty
string is a possible publication key. Activated exact allowlists use escaped
alternation and absolute `\z` endings: PCRE `$` can match before a final newline.
No owner-wide event wildcard or seven-target publication ceiling remains.

## Metadata and activation handoff

`route-contracts.json` has `format_version: 1`, `route_format: 1`, and explicit
`activated_integration` / `activated_quarantine` arrays. An integration entry has
`source`, `target`, `event_type`, integer `schema_version`, and `review_ref`.
Its exact key is `source.target.fullOwnerQualifiedEventType`, preserving the
T-011/T-925 route. The full event type's source and canonical positive uint32
version must match those fields, and the AMQP route must fit 255 bytes. Repeated
owner words inside a valid full type remain valid. A quarantine entry has
`owner`, `source`, versioned `failure_type`, and `review_ref`; its route is the
retained `owner.source.failureType` format.

The assigned Go test leaf contains a deterministic permission compiler/oracle
and strict metadata decoder: duplicate keys/routes, noncanonical fields, unknown
fields/owners, missing arrays/review references, malformed versions/types and
overlength routes fail. Compiled permissions must exactly equal checked-in
definitions. All synthetic entries live in test functions and temporary fixture
imports; none are business activation metadata.

This leaf does not introduce a production provisioning binary. A later reviewed
activation must supply actual reviewed metadata, update definitions to the exact
compiled grants, and deliberately replace the empty-business-activation guard in
the test. The compiler checks reference shape; the migration authority must
verify the referenced approval and its source/target/schema scope. Broker grants
cannot authorize company, party or stream objects; source admission and receiver
validation remain required.

For an existing installation: capture broker/backlog and delivery ambiguity
evidence; stop old runtimes and explicitly close their AMQP channels; audit actual
bindings and role grants; import the complete restrictive definitions under the
separate migration identity; verify new connections and custody/admission/schema
compatibility before resuming. Definition import alone is not a channel fence or
proof that cached permissions have been invalidated. No queue/history deletion,
automatic bootstrap or production cutover is performed by this task.

Topic READ applies to binding keys, rather than message delivery routing keys.
Runtime topic READ is denied because infrastructure owns the retained bindings;
intake delivery access is its queue READ permission. The live probe separately
grants a temporary provisioning identity the exact literal `*.documents.#`
binding key and verifies that `*.retail.#` fails. The infrastructure audit also
detects an unexpected cross-owner copy binding, then verifies the restored
original topology. RabbitMQ's
[access-control](https://www.rabbitmq.com/docs/access-control) and
[definition import](https://www.rabbitmq.com/docs/definitions) documentation
were consulted for these distinct permission/import semantics.
