`NewRecord[T](envelope, schema, target)` revalidates the typed owner payload,
including an envelope previously decoded from JSON. It seals serialized JSON
bytes and SHA-256 before persistence. The original metadata, reference IDs,
string revisions and integration sequence are retained. There are no public
mutable byte/routing fields. The route is
`<source>.<target>.<eventType>` on the approved `justix.integration.v1` exchange;
owners are validated and overlong AMQP routing keys rejected.

`NewInserter(tx, owner)` requires a transaction handle. Bind it alongside the
appender, synchronous guards and receipt ports using the exact T-009 factory
transaction. Service application/domain packages continue to consume their own
typed ports; they do not import this GORM adapter or access its database.

`Insert` selects a matching local domain event and inserts the sealed record.
The matching event must have the same owner, event/type/version, aggregate ID,
aggregate revision, positive integration sequence and envelope metadata,
including company, actor and operation/correlation/causation references.
An internal event's NULL sequence cannot match. No universal immutable company
history rule is introduced: each event's own metadata must agree. The typed
integration payload is separately schema-approved and need not equal the stored
domain JSON. Subscriber authorization and permitted payload meaning are owner
contract responsibilities, not inferred from a valid target name.

The caller must propagate all errors to `Transactions.Run`. Duplicate event IDs
or stream positions are errors, never silently retargeted or treated as command
replays. Receipt-based command recovery remains T-017/owner logic. Empty insert
is a no-op for internal-only batches. No commit, broker publication, relay retry,
automatic transaction retry or external side effect is performed here.

**Multi-recipient subscribed streams remain unimplemented.** The approved
T-008 table has one routing key per event ID, while T-006 routing selects one
target. Architecture §5 requires every authorized subscriber to receive every
integration sequence position for its subscribed stream. Alternating targets
would create gaps and does not solve fan-out. Do not manufacture new event IDs
per recipient or weaken sequence continuity. Owner subscription activation that
needs multiple recipients requires a coordinator-reviewed fan-out contract and
any corresponding schema/topology amendment first. The coordinator explicitly
confirmed this bounded single-target implementation and limitation.
