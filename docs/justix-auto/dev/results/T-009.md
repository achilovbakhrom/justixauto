`NewTransactions[U]` receives a GORM database and an adapter-only factory binding
transactional repositories. `Run(context.Context, func(U) error)` exposes only
the owner's typed port set to the application. Owner app/domain/port packages
must not import this infrastructure package; their adapter implements the owner
UnitOfWork interface using it. There is no GetDB/context service locator.
Factories must bind every repository to the supplied transaction, and neither
the port set nor repositories may escape the callback.

`NewAppender(tx, owner)` rejects a nontransactional database handle. `Append`
accepts one `Batch{Expected, Events}` per aggregate stream. It validates all
pending revisions, acquires transaction-scoped PostgreSQL advisory locks in
sorted stream order (including absent streams), checks authoritative current
revisions and contiguous existing history, then inserts. SQL uniqueness remains
the second concurrency fence. Hash collisions only serialize unrelated streams.
Call once with all affected streams where possible; callers must propagate
errors to `Run`, which never retries callbacks automatically.

`NewEvent` requires an explicit owner-declared T-007 payload schema;
`NewInternalEvent` additionally requires an unset integration sequence. Internal
events use the shared metadata validator privately and persist SQL NULL for
their integration sequence. `IntegrationEnvelope()` exposes only integration
events for the downstream transactional outbox adapter. Aggregate revisions and
emitted integration positions are checked independently and contiguously.

Per-event actor/company validity and schema validation are enforced. Shared
append does not invent a universal immutable companyId rule: the approved stream
key is owner/type/id, and owner commands must authorize actor/company/custody or
other business transitions. A regression preserves another schema-valid company
ID at the next revision without rewriting metadata. This grants no transfer or
cross-company authorization; owner command admission remains required.

One transaction can append multiple streams and invoke typed guard, outbox and
receipt ports. Callback/factory errors, cancellation before commit and panics
roll back; a panic is preserved. Every commit error returns
`ErrCommitOutcomeUnknown` with the original error. Neither a lost reply nor a
subsequent cleanup rollback is treated as authoritative failure or success.
Recovery must consult the owner's durable command receipt and idempotent command
protocol. No network/broker side effect belongs inside the transaction callback.

  expected-revision conflict. Reversed multi-stream batches acquire sorted
  locks and produce one atomic winner without a lock-order deadlock.

  integration gaps, invalid/empty batches, mixed streams, repeated streams,
