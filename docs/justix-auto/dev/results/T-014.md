## Composition and API handoff

`NewContract` seals consumer/K, local/source owner, kind, exact generation label
and contract identity. It copies owner-declared source/generation/guard fence
requests. `NewPosition` validates exact original envelope bytes through an
explicit typed event schema and owner scope validator, retaining the original
SHA-256 and envelope stream/position. A known irrelevant event remains schema-
and scope-validated before its explicitly configured no-op.

`NewCheckpoints[U](ctx, tx, prepared, contract, bind)` accepts the actual outer
ReadCommitted transaction and T-926 `PreparedFences`. It requires the adapter's
complete catalog/receiver/additional fence set before binding typed owner ports,
and checks its owner/runtime revision-4 marker and exact 000004 artifact digest.
No method starts or commits a transaction, acquires a late advisory fence,
publishes, acknowledges, retries an effect or makes a source request. Caller
errors must propagate to the outer `Transactions.Run` so every partial write
rolls back. Owner adapters must actually declare all source/guard/generation
prerequisites before any head/job/inbox/effect locks; this API cannot discover
uncooperative business writers or prove an arbitrary callback is local SQL.

Fence declarations are local execution prerequisites rather than source event
identity. `Contract.same` compares immutable consumer/stream/contract identity;
it does not compare fence slices. Every receiving adapter independently requires
its own complete declared set before binding or effects. A weaker event claim
cannot remove that adapter's required generation/guard/source locks. The live
missing-generation-fence probe fails before the owner factory runs.

`VerifyBootstrap` invokes the authenticated source verifier outside SQL, sealing
the high-water, snapshot/no-snapshot evidence and purpose/scope references. Zero
requires explicit newly-empty source proof; positive high-water rejects that
zero-only proof. `InstallBootstrap` requires exclusive catalog and receiver
fences, a mandatory current local authority/admission recheck, and a typed local
snapshot installer. Bootstrap/snapshot/checkpoint writes share the same outer
transaction as T-920's future admission/enrollment/backlog work. Exact installation
request replay reads retained evidence and skips the snapshot; different input,
request or reused consumer meaning cannot reset progress. Consumer contract,
kind and generation also match existing bootstraps across its stream universe.
The returned bool is an uncommitted candidate, never a receipt.

`CheckNext` revalidates current owner authorization, exact bootstrap and contiguous
checkpoint identity, then returns an opaque adapter/transaction/position/hash
candidate only for +1. A greater position returns `*Gap`; a missing, behind or
inconsistent checkpoint returns a reconciliation hold. `Advance` verifies the
same candidate and matching inbox event/hash before its typed effect, then
increments position/revision exactly once. Irrelevant events skip the effect
but advance the checkpoint. Wrong/reused/foreign candidates cannot run effects.

T-013 direct composition prepares fences in its factory before inbox acquisition.
T-922/T-923 caller composition prepares all fences before head/job/inbox, inserts
or reads inbox, checks/applies the sequence effect, then completes its exact job
with T-923's final live lease fence. T-014 supplies no job runner or broker ACK.
Every custody duplicate must call `VerifyDuplicate` before sequence-dependent
job completion: absent/behind/prefix-only checkpoint evidence is a hold. The
exact last position additionally matches checkpoint last event/hash and retained
inbox. Older positions require a non-nil typed **same-transaction retained-coverage
verifier** after the shared adapter checks bootstrap, stream, position and inbox
identity/hash. Its owner port must verify original retained event evidence for
that position/stream; a larger integer, current object lookup or default true
callback is not evidence. The live tests cover absent and rejecting verifiers.
Duplicate verification never invokes `Advance` or repairs missing history.

## Gap, crash and recovery protocol

The outer effect transaction must return `*Gap`, rolling back inbox/effect/
checkpoint/job work. `RecordGap` refuses that same transaction ID and rereads
checkpoint/bootstrap in a separately prepared local transaction. It records
immutable blocked identity/hash and an initial requested attempt, or an explicit
resolved root if another worker already covered the interval. Requests have
caller-supplied stable UUIDs; exact replays compare retained evidence. Different
requests for an already recorded blocked event conflict rather than replacing
the root. A restarted worker uses `FindGap` with the original validated envelope
to discover its retained root and exact current attempt IDs. Changed bytes under
that event ID fail. The method requires the same current authorization/fences.

`AppendAttempt` checks the current chain tip, request identity, safe reason code,
verified recovery manifest and authoritative progress. One successor wins a
concurrent race. Held recovery requires explicit resume before another request.
Stale holds return a reconciliation hold so the caller records an explicit
resolved action using a fresh request; no changed request is silently normalized
into an old receipt. Attempt writes never advance a checkpoint. Unknown commits
discard candidates and reconcile exact persisted request evidence before any
new source operation.

`ReadRecovery` accepts a pool, rejecting a transaction handle, and loads one
committed requested tip with current bootstrap/contract identity. It requires a
current source purpose/scope authorization callback. A request whose lower
boundary no longer matches checkpoint+1 is stale; `FindGap` plus a new requested
attempt records only the remaining missing interval. No reference alone grants
source or process history authority.

`FetchRecovery` has no database handle. The injected authenticated source port
fetches only that finite original interval outside SQL; the whole batch must
match its versioned exact-byte manifest, source/stream, IDs, contiguous positions,
schema and scope before any submission. `SubmitRecovery` passes copied original
bytes through the configured ordinary path: `DirectWithoutBrokerDelivery` has
no broker ACK, while `CustodyIntake` means durable intake rather than business
completion. Partial submission is safely repeated through ordinary dedup. It
never ACKs the blocked original or adopts current aggregate state. The outer
ordinary path must revalidate authority again when applying/intaking the bytes.
Resolution is recorded only from authoritative contiguous checkpoint progress.

## Scoped blocker and remaining activation gates

**Space-only retained generation labels remain blocked by immutable 000004.**
Its `consumer_bootstraps.generation` check uses `length(btrim(generation))>0`,
while existing 000002 admission labels use `length(generation)>0`. `NewContract`
now accepts exact nonempty valid UTF-8/NUL-free labels without trimming; padded
and tab-only labels install unchanged for process and projection. A single-space
label passes the Go and admission boundaries but fails the existing 000004
constraint, rolling back the complete install. Both kinds have explicit live
rejection tests. No label is normalized, renamed or silently dropped. The
coordinator confirmed this evidence and is handling a separately reviewed
forward storage correction; T-014 does not rewrite 000004 or claim full retained-
label compatibility before that correction is integrated.
