## Adapter and T-919 handoff

`NewSourceStream` seals one owner/type/canonical nonzero UUID. Constructors
defensively copy schema lists and reject empty/duplicate/foreign/invalid versions.
`NewSourceAdmission` seals the concrete destination, immutable contract
ID/version/digest, scope/purpose/authority and bootstrap evidence. These are
owner-supplied technical assertions after business authorization, not independent
proof of a data grant. No actual company, recipient or schema admission is seeded.

Bind `NewSourceAdmissions(tx, owner)` to the exact T-009 UnitOfWork transaction.
Call `Fence(ctx, allStreams...)` once, before any append or other stream locks.
It validates the owner/schema marker and acquires every stream in T-009 order:
`hashtextextended('justixauto:eventstore:'+owner+':'+type+':'+uuid,0)`.
Every subsequent operation must name one of that complete fenced set. Do not
extend the set after locking or use concurrent goroutines within one transaction.

`Admit` reads contiguous authoritative domain/integration history under that
fence and requires the exact integration high-water. A zero checkpoint additionally
requires explicit new-empty-stream evidence and no existing domain events,
including internal-only history. Nonzero admission needs a bootstrap reference;
the owner still supplies the separately authorized snapshot/checkpoint through
its authenticated port. This leaf does not fetch or broadcast snapshots, approve
process catch-up or establish the receiver's checkpoint.

`Change` appends close/hold/resume evidence against the exact current chain tip.
The change checkpoint must match current fenced high-water. Close records the
drain boundary, retaining earlier obligations. Hold updates unsent children of
that root admission and blocks active-range emission; it never clears sent
status or deletes bytes. Resume requires an explicit retained-work authority,
clears only this chain's own hold marker and does not reopen a closed range.
Different security/migration holds remain. Re-admission uses a fresh ID and
checkpoint. Reference presence does not settle feature-specific revocation or
the disposition of in-flight/already received bytes.

Effective state is replayed from all immutable records, independently of insertion
order/timestamps. Missing parents, cycles/branches, metadata drift, invalid
transitions and overlapping ranges for the same destination fail closed, even
when inactive. Adjacent drained/re-admitted ranges are permitted. No missing
deployment or changed catalog cancels an obligation.

The owner supplies a sealed `SourcePlanRule` for the concrete stream and permitted
emission schemas. A distinct nonempty empty-plan authority reference is required
to emit with no active recipient; missing configuration does not become `[]`.
For T-919's writer:

1. Fence all affected streams, then append all their events through T-009.
2. Resolve each schema-validated envelope with
   `admissions.Resolve(ctx, rule, envelope)` in that same transaction.
3. Resolve verifies that the exact local event/type/schema/revisions belong to
   the current PostgreSQL transaction (`xmin=pg_current_xact_id()::xid`). It
   supports every position in a just-appended batch, rejects committed-history
   re-planning, selects every active recipient and rejects any unapproved schema
   or active hold. No caller-provided destination subset enters the resolver.
4. `DeliveryPlan` seals the event/stream/sequence, sorted distinct recipients,
   original admission IDs/contract references, authority, issuing adapter and
   immutable-evidence fingerprint. `Recipients()` returns a defensive copy.
5. Immediately before parent/children persistence, call
   `admissions.ValidatePlan(ctx, plan)` on the same adapter. It rejects an escaped
   candidate, changed admission evidence or a rolled-back local event. A plan
   is a transaction candidate, never a committed delivery receipt.
6. T-919 owns serialization once, exact local-envelope matching, parent plus all
   children and receipt/guard atomicity, explicit messaging mode checks and the
   existing `insert.go` adaptation. Persist each recipient's root `AdmissionID`;
   its immutable row carries the contract references. Never resolve in the relay.

Bootstrap and change evidence are encoded as immutable JSON in T-917's opaque
`bootstrap_ref` column, preserving the original reference, explicit empty proof
or change checkpoint/retained-work reference. Existing independently reviewed
opaque migration references are not rejected merely for using another encoding.
Admission evidence may be staged in legacy mode; this adapter never activates
custody. Held-delivery mutation is subject to T-917's custody-mode trigger.

## Discovered cross-leaf route blocker

T-011's established route for event type `inventory.fixture.changed.v1` and
recipient `retail` is `inventory.retail.inventory.fixture.changed.v1`.
T-917 currently reconstructs a schema name by prepending `inventory` to the suffix
after the first two components, producing `inventory.inventory.fixture.changed.v1`.
That does not match the correct admission allowlist.

Minimal reproducer on the pinned T-008 + T-917 fixture:

- Admit a source stream to retail with schemas `["inventory.fixture.changed.v1"]`.
- Append its first integration event and stage a parent with that event ID,
  exact envelope and `[{"destination":"retail","admission_id":"<root UUID>"}]`.
- Insert its child using T-011's established route above.
- T-917 rejects it with `delivery schema is not admitted`, SQLSTATE `23514`.

The coordinator was notified and explicitly retained the established T-011
route contract. This leaf makes no route change; its route-length check uses
the existing writer helper. The test-only `sourceStageFixture` uses T-917's
currently accepted shorter `inventory.retail.fixture.changed.v1` route solely
to test retained-obligation hold/drain and commit faults. That helper is **not**
production routing or proof of T-011/T-917 composition. A separately assigned
forward schema correction and its live compatibility QA remain an integration
gate for T-919/intake/relay. No migration or another worker's leaf was amended.
