## Changed paths

- `pkg/eventstore/schema.sql`: explicit, atomic psql installation template for
  each of the seven owner databases. Installs events, command receipts, outbox,
  inbox, operations and completed operation-step receipts under `eventstore`.
- `pkg/eventstore/schema_test.go`: opt-in real PostgreSQL integration checks in
  one test-owned random Docker container, without host ports or named volumes.
- This assigned result file.

The installer accepts `owner_service` and an already provisioned `runtime_role`.
Run it as the migration/database owner. It creates no roles, passwords, business
fixtures, cross-database links or automatic startup migrations. A repeat install
fails atomically; versioned owner migrations must manage subsequent changes.

The runtime role owns no schema/table and receives SELECT/INSERT on history and
receipts, with narrowly enumerated scheduling/process UPDATE columns. It cannot
UPDATE/DELETE/TRUNCATE events, mutate durable receipt identity, rewrite outbox
bytes/routing, or change admitted operation scope/hash. A trigger prevents an
established commit/abort decision from being reversed or reset to undecided.
There is no automatic purge, business expiry or timeout-driven terminal result.

Runtime role checks reject the migration/database owner, elevated role flags,
and reachable predefined/elevated roles, including NOINHERIT memberships usable
with SET ROLE. A final transactional privilege audit catches broad inherited or
default table/schema grants. T-005 database-owner credentials must therefore be
used for migration only; service runtime credentials must be separately
provisioned for the narrow role by the owning runtime/infra task.

Events have unique IDs, unique aggregate type/ID/revision and independent
optional integration positions for internal-only events. Revisions are positive
signed bigints; schema versions cover T-007's uint32 range. UUID actors and
owner-qualified/version-matching event types are enforced. Only identity may
store a null company. SQL preserves payload objects; approved owner schema
validation and secret/PII filtering remain required before persistence.

Command uniqueness includes actor/company/command/target/key with NULLS NOT
DISTINCT for global commands and creates. Only a nonsecret digest/HMAC and safe
typed receipt are stored; no request-body column exists. Outbox retains immutable
bytes with a checked SHA-256 digest, routing, stream/sequence and scheduling
metadata. Inbox uniqueness is per consumer/event, and completed steps are unique
per operation/step. No foreign keys cross owner databases.

## Boundaries

No blocker in T-008. This schema does not implement expected-version contiguous
append, aggregate replay, handler authorization, canonical hashing/HTTP replay,
relay claims or publisher confirmations, checkpoint/gap recovery, process
recovery, durable quarantine, migration version tracking or service composition.
Those remain assigned downstream tasks. SQL constraints and transactional tests
do not establish broker delivery guarantees or parent B-01 acceptance by
themselves. Owner application schemas must keep sensitive data out of generic
JSON receipt/event fields; this template is not a PII classifier.
