`NewConsumer[U]` binds an owner-declared typed port set through the existing
T-009 transaction runner. Its adapter factory receives the single GORM
transaction; the effect callback receives only U and an immutable event envelope.
The factory must bind every local repository to that transaction and must not
capture another database or let transaction-bound ports escape the callback.

`Consume` copies the received bytes, structurally decodes the T-007 envelope,
and invokes the mandatory owner validator before persistence, including for
duplicates. The validator must decode the allowlisted payload schema and check
the permitted source/scope. Business scope and sequence admission remain owner
responsibilities; this technical adapter grants no authorization.

The unchanged T-008 inbox stores `(consumer_name,event_id,envelope_hash)`.
`INSERT ... ON CONFLICT DO NOTHING` serializes competing duplicates. A fresh
delivery invokes the typed local effect/checkpoint callback inside the same
transaction. A duplicate reads the committed hash using a fresh ReadCommitted
statement snapshot and no-ops only for identical received bytes. Different
bytes under the same event ID return `ErrEnvelopeConflict`, preserving evidence
and withholding ACK. Consumer names separate subscribers/projection generations.

The supplied ACK callback runs only after a confirmed transaction commit. Its
transport binding must acknowledge the single delivery, e.g. `Ack(false)`.
Validation, handler, database and commit errors do not invoke ACK. A successful
commit returns `Applied` or `Duplicate`; ACK failure retains that local outcome
and returns `ErrAcknowledgment` plus the original error. Any commit error returns
`Unconfirmed` and preserves T-009 `ErrCommitOutcomeUnknown`. Redelivery resolves
an ambiguous commit through the durable inbox without repeating a stored effect.
