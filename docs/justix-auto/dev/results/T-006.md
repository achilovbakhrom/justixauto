## Result

Implemented the restricted `/justixauto` vhost for the seven approved service
owners. The imported topology has durable topic exchanges, a durable quorum
inbox and quarantine queue for each owner, and explicit bindings whose routing
keys are `<source>.<target>.<event>` for integration traffic and
`<consumer>.<source>.<failure>` for quarantine traffic.

Each `svc_<owner>` principal has no administrator tags, cannot configure broker
objects, reads only its own two queues, publishes only to the two approved
exchanges, and can use only a declared owner as the integration source/target.
Service principals deliberately import with empty password hashes, so the
definitions contain no usable credential. The later local runtime must inject
credentials before callers can connect.

The integration test validates the exact vhost, owners, exchanges, queues,
bindings and resource/topic permission regexes. Its opt-in live case passively
checks the imported durable objects on RabbitMQ 4.3.5, publishes a persistent
message with `mandatory=true` and confirms that an unbound routing key produces
`basic.return` code 312 `NO_ROUTE` while the publisher confirmation is ACKed.
That confirms the broker behavior required by a relay; it does not claim that a
broker dependency alone supplies outbox/inbox or exactly-once delivery.
