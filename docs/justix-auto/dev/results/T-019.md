# T-019 developer result

## Outcome

Implemented the shared fixed-precision money and policy value package. Money is
stored as an immutable arbitrary-precision integer with a canonical signed
`amountMinor` representation limited to 38 digits. Each value retains the exact
currency code, exponent, and exponent-version identity used to create it;
arithmetic rejects any mismatch and never rescales or performs FX.

The public JSON shape remains exactly `{amountMinor,currency}`. Parsing requires
the caller to supply the selected versioned currency definition, rejects unknown,
duplicate, missing, non-string, noncanonical, and trailing input, and therefore
does not infer historical exponent metadata from a code.

Added decimal rate strings which preserve policy-defined scale and do not assign
percent, basis-point, sign-range, period, or rounding meaning. Added canonical
Gregorian `YYYY-MM-DD` values, inclusive/open-ended effective periods, and an
explicit generic policy value. Missing, zero-value, or out-of-period policy data
returns `POLICY_UNRESOLVED`; there is no demo/default fallback.
