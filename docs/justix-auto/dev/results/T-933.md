First, a single `migrate.Up` targeting `[1,12,17]` could complete 12, fail before
17's dirty transition, reconcile the exact clean 12 receipt and return nil. The
fix preserves `recorded-completion` as the authoritative outcome for artifact
12 and retains its durable report, but compares that reconciled version to the
sealed requested profile head. If they differ, `runPrivate` returns
`errRequestedHeadNotReached`; it never represents the whole command as complete.
This does not relabel 12, discard its receipt, replay either artifact or dirty the
ledger. An exact intermediate recorded report may be reused only after its full
artifact/request/hash/provenance shape validates, allowing a later explicit run
to continue from the authoritative clean head.

Second, resolved report reuse now has status-specific validation. Pending,
retained-incomplete and recorded-completion reports must identify a real sealed
profile artifact, nonzero UUID, exact SQL/profile digests and exact configured
provenance; version 1 additionally requires the sealed baseline request UUID.
A verified no-op must name the exact profile head and contain no fabricated
request, SQL digest or provenance. Wrong/nonexistent versions, missing requests,
wrong SQL, missing/wrong provenance, malformed digests and a no-op below head no
longer release the durable report path. This validates retained runner evidence;
it does not claim protection from a trusted administrator deliberately replacing
both release files and database evidence.
