## Delivered contract

`@justixauto/test-kit` is a private development-only source TypeScript package.
All package dependencies are devDependencies. MSW 2.15.0 follows the coordinator's
`state/approvals/T-035-msw-pin.md` amendment on main; Playwright 1.63.0 and the
React/RTL/jsdom versions use the existing approved pins. Root lock ownership
remains with the coordinator. Build performs strict source/config typechecking,
as the API source package does; no generated production runtime is claimed.

- `checkedFixture(schema, value)` takes a feature-owned synchronous DTO schema,
  checks a copied JSON snapshot, rejects coercing/transforming schemas, and
  returns a deeply frozen value. It rejects unknown schema fields, unsafe
  revisions when the feature schema requires them, undefined, sparse/inherited
  array slots, accessors, cycles, symbols, dates, bigint, nonfinite numbers and
  negative zero. Schema diagnostics and raw fixture bodies are not copied into
  errors. The helper does not invent an owner DTO, money policy or access matrix.
- `jsonHandler({method,url,request,response})` validates response fixtures before
  registration and validates the request using an explicit feature-owned
  extraction callback plus schema. Serialized response bytes are snapshotted.
  Body-bearing statuses are explicit; 204/205/304 are rejected by this JSON
  helper. Consumers may use explicit MSW handlers for intentional bodyless,
  malformed or network-fault scenarios. A scenario is a static fixture, never
  proof of server authorization, command replay or durable state changes.
- `createFixtureServer(...handlers)` wraps MSW's Node interceptor. Unmatched
  requests cannot fall through to a backend. Resolver/unhandled failures are
  retained for `assertClean()`, `reset()` and `close()` even if the app catches
  the fetch result. MSW renders thrown failures as a local 500; that response
  alone is not a passed negative test. Use one server per test process, start
  with `listen()`, call `reset()` after each test, and `close()` after the suite.
- `captureComparison(...)` requires an explicit schema, synthetic state ID,
  viewport and two loopback targets. Each target supplies pre-navigation setup
  and post-navigation interaction/readiness assertions. Each gets a fresh
  context and its own frozen state snapshot, with ru-RU, Asia/Tashkent, light
  scheme, reduced motion, device scale 1 and fixed Date. Full-page CSS-scale
  PNGs disable animations/carets and wait for fonts; uncaught page errors fail
  capture. Both contexts close on success or failure. The returned manifest
  records environment/URLs/state ID, not raw state. The helper captures evidence
  and deliberately does not assert visual equivalence or infer reference state.

The shared Playwright config at `tests/e2e/playwright.config.ts` has desktop
1440×1000 and narrow 600×1000 Chromium projects, one worker, no retries,
forbid-only, failure evidence and no automatic seed/server startup. Feature
tasks add actual journeys. Its currently empty feature suite must not be
reported as a passing end-to-end application suite.

## Reproduce browser evidence and its limits

With pinned Node on PATH, from this task root:

```sh
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/justixauto-playwright-1.63 \
  node node_modules/@playwright/test/cli.js test \
  --config docs/justix-auto/dev/qa/T-035/developer-playwright.config.ts
```

For a fresh machine first run the pinned CLI's `install chromium --only-shell`
with the chosen `PLAYWRIGHT_BROWSERS_PATH`. The developer config starts only a
loopback Vite server at port 4195 and uses the integrated T-034 synthetic React
fixture at `dev/qa/T-034/developer-fixture.html`, not a business page. Both sides
intentionally load that same fixture to prove repeatability and independent
storage; a synthetic sessionStorage marker exists only as the isolation probe.
The four token scopes run at both viewports. Assertions verify the fixed Date,
viewport, fresh storage, zero synthetic writes, opened dialog and matching
non-sensitive field value before capture. All eight PNG pairs match exactly.
Invalid schema/viewport/URL fail before capture, and readiness exceptions leave
no new contexts behind. Sixteen PNGs and eight environment manifests are under
`dev/qa/T-035/developer-*`; the narrow Admin capture was also inspected visually.

These captures do not compare business HTML to implemented applications and
do not claim screen parity. There are no new app shells, menu entries, feature
