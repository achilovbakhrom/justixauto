Digests are lowercase hex SHA-256. The runner must verify the installed 000002
artifact and compute the exact 000003 digest before supplying them. SQL checks
the pinned prior digest, correction digest shape, owner/runtime identity and
nonempty references; it cannot verify its own input file, a real backup, closed
AMQP channels or concrete business authority. Tests use explicit synthetic
references and no service/AMQP processes.

The script takes ACCESS EXCLUSIVE table locks in the approved order: legacy
outbox, legacy inbox, mode, outbox messages, deliveries, dispatch messages,
enrollments and jobs; then it locks the singleton mode row. Every lock wait has
a five-second timeout. This bounds lock waiting, not total retained-data scan
time. Incompatible routes or corrected allowlists abort before function changes.

`eventstore.messaging_route_compatibility` contains the immutable singleton
owner/runtime identities, base schema version 2, migration revision 3, route
format 1, both artifact digests, backup/stopped-runtime/compatibility references
and finite installation timestamp. Runtime receives SELECT only; PUBLIC receives
no marker grants. Direct, column, default, inherited and SET ROLE-reachable
permissions are audited, including broad UPDATE/DELETE/TRUNCATE/MAINTAIN,
delegable grants, migration-function execution and legacy writes in custody mode.
Existing work-column grants are preserved. Marker UPDATE/DELETE also encounter
the existing immutable-content trigger.

Base `messaging_mode.schema_version` stays 2 and its one-way legacy→custody
transition is unchanged. The correction may install in legacy mode, or in an
existing custody store whose retained routes and allowlists are already
compatible. Shortened records and incompatible admissions stop installation and
need a separately reviewed disposition. Reinstallation and even a preexisting
incorrect marker fail; the script never repairs the marker in place.

T-022 and custody compositions must require the complete matching marker tuple,
both artifact identities and their existing mode/owner/ACL/adapter/admission
checks. Schema version 2 alone is insufficient. Legacy-only owner scaffolds do
not gain custody readiness. T-919/T-921 must additionally compare the validated
envelope's actual source, full event type and schema with its route; the SQL
continues treating envelope bytes as opaque. T-924 supplies the broker leg.
