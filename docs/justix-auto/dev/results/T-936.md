## Delivered behavior

The existing shared fetch path now exposes frozen `responseContractVersion: 1`
and captures positive safe integer construction limits (8 MiB / 128 defaults).
It reads actual decoded stream bytes into an amortized bounded buffer, ignores
Content-Length for allocation/limits, cancels on overflow/abort and does not wait
for an uncooperative cancellation promise. Intrinsic byte-array branding accepts
real cross-realm Fetch chunks and rejects wrong typed arrays/spoofed tags.
T-935's unchanged decoder supplies all raw grammar/Unicode/numeric checks;
there is no alternate decoder or `response.json()` path.

Legacy callers preserve finite-number behavior, request/receipt/result shapes,
same-origin credentials, path/header checks, no-store requests, disabled redirects
and one fetch without retry. Reviewed tightening rejects malformed raw JSON and
oversized/deep responses. A signal already aborted before dispatch produces local
`invalid-request` with zero fetch. A dispatched unsafe transport error, invalid
response or unexpected status remains an unknown owner outcome; no rollback or
automatic retry is inferred. HTTP 429 is an additive typed error status.

`ResponseContract` captures exact declared statuses, endpoint error parsers and
header rules before IO. It rejects missing/extra/unknown rules and unsupported
profiles. Profile requests use exact safe-integer decoding. The success or exact
status-specific error parser completes before metadata validation. Common receipt
validation is additional; it is never the endpoint error fallback for a profile.
Undeclared statuses remain `unexpected-status` without a sink call.

For auth, an explicit `AuthExchange` prepares once immediately before fetch.
Unsafe methods require its validated token; GET never sends it. Competing
case/underscore token aliases reject before prepare. The interface supports
ordinary object/class/prototype methods and synchronous callable getters, captures
each method once before dispatch, and preserves its receiver. This does not apply
the separately specified generated semantic table's own-data-function rule to
legacy Schema/AuthExchange implementations. Throwing getters fail before fetch.

Only after complete body validation and the allowlisted CSRF, Retry-After,
Cache-Control and media checks does the transport synchronously call `accept`
once. Exactly true accepts; false, throw or another value suppresses result
delivery. Native returned/thrown Promises are rejected and disposed through the
captured intrinsic `then` with constant handlers. Callable/accessor thenables
reject without reading/invoking `then`; ordinary DTO data keys named `then`,
`constructor` or `__proto__` remain data. Schema callbacks get the same runtime
synchronous guard. No catch-all branch fallback or diagnostic retention exists.

Metadata is frozen and ephemeral, passed only to the trusted acceptance port;
it is absent from generic results/receipts, logs, caches and storage. The port
must check its current captured ticket before atomic mutation. The transport does
not reset epochs, release another ticket, create session state or roll back a
throwing/malicious sink. The actual reviewed controller is T-944, concrete auth
semantics T-943 and generated bindings T-937–T-942/T-641.

The three generator regression fixtures now copy `responseJSON.ts` beside their
existing `client.ts` copy. Coordinator explicitly added this third leaf and
T-640 dependency at main `991db15`; all existing generator assertions and behavior
are unchanged. No root manifest, lock, generator, decoder or application UI leaf
was changed.
