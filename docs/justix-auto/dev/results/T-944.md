## Scope and behavior

Only `web/packages/api/src/authEpoch.ts`, its adjacent test, and the API manifest's
`./authEpoch` export change. The controller imports shared transport types only.
It has no React, generated auth DTO, session package, storage, timers, retry queue,
telemetry, database, cookie access or production policy dependency.

`createAuthEpoch` requires the cooperative transport version 1 and captured own
data-property bindings. `execute` takes an exact operation purpose, expected local
phase set, generated/validated request configuration and a synchronous typed
classifier. The ten purposes distinguish challenge creation from verification;
fixed approved paths/methods and no handshake If-Match/idempotency key are checked
before dispatch. The actual shared client performs raw body/schema/metadata
validation before the controller's one-shot acceptance callback.

One ticket owns the slot until the transport promise settles. Invalidation aborts
the request but does not free that slot. Epoch exhaustion fails closed at the
largest safe integer. Each prepare and accept is one-shot; classifier reentrancy
must pass a second epoch/slot/state check before mutation. Only the exact ticket
releases its slot. Cancellation/stale dispatched writes leave uncertain memory;
no rollback or successful logout is inferred from abort or validation failure.

Logout clears visible state first, using a private old-token closure only for its
new-epoch exchange. If an older exchange remains unresolved it returns busy,
retains no queued secret and cannot claim logout success. Explicit invalidation
supports login intent, context/revocation hints, navigation and unmount. T-055 must
call it on those intents and synchronously clear its own UI/query state; this
pure controller cannot observe React navigation or independent requests.

Anonymous SESSION_REQUIRED adopts only CSRF. Restricted results cannot populate
protected session state. Full context and token are adopted together. Step-up
challenge creation retains existing session assurance and stores only the current
view; verification replaces context/token. Enrollment confirmation stores codes
in the current view and enters context-unresolved, requiring explicit acquisition.
Recovery acceptance grants no session; successful logout/recovery completion clear
memory. A validated AUTH_OUTCOME_UNKNOWN cannot be treated as an ordinary error.

Returned outcomes contain only fixed kind/epoch/status fields. No ApiResult body,
receipt, CSRF or one-time secret is returned. Current session/restricted/view data
are available only to injected synchronous view visitors, copied as immutable JSON
data without accessors, cycles or caller-owned mutable references. Native rejected
Promises from invalid classifiers are silenced without arbitrary thenable getters.
Visitors/adapters are trusted application code: JavaScript cannot prevent them
from retaining values they receive or guarantee physical memory zeroization.
Current-view clearing and epoch checks constrain controller-owned retention.
