## Delivered contract

`@justixauto/api` exports source TypeScript from `src/client.ts`, with
`@justixauto/api/queryKeys` exporting the immutable query-key helper. The build
checks the source export contract; it does not claim generated JS artifacts.
The package adds no runtime or tooling dependencies and uses the approved root
TypeScript/Vitest tools. Its named Vitest project is discovered by the root runner.

`createApiClient({origin, fetch?}).request({path, schema, successStatuses, ...})`
accepts only rooted same-origin `/api/v1/` owner/operation routes. Ambiguous
traversal, external URLs, fragments and non-API page paths fail before fetch.
Requests use `credentials: same-origin`, `mode: same-origin`, `cache: no-store`
and `redirect: error`. Reserved transport/identity headers cannot be supplied
through the extension headers. Exact context revision, quoted If-Match and UUID
idempotency headers have separate validated inputs. Required action preconditions
remain endpoint-owned: the shared transport does not infer mutation semantics
from a verb or incorrectly require business-ledger keys on authentication routes.

Each feature injects its synchronous schema adapter and explicit permitted
success statuses. HTML/malformed JSON and rejected schemas produce an
`invalid-response` result without copying the raw body or schema diagnostics.
The explicit logout 204 exception passes `undefined` to its adapter. A 202 is
accepted only when selected by the feature and remains its typed pending DTO.
The shared error receipt validates the approved common structure, including
optional UUID operationId; owner-specific field error values remain unknown.
400/401/403/404/409/412/422/428/503 are discriminated `http-error` results.
Unexpected statuses remain distinct and are never interpreted as success.

There is no automatic retry, response cache, logging, storage access or token
persistence. A network failure/abort of a write reports an unknown outcome,
without claiming durable cancellation. Invalid/unexpected responses are also
not authoritative failure receipts: command/session consumers must reconcile
their operation or original idempotency key according to their own contract.
Read retry scheduling, epoch cancellation and receipt recovery are subsequent
consumer responsibilities. Extension headers can carry the future approved
session CSRF protocol; this task does not invent a header name or token source.

`queryKey(scope, resource)` returns the exact architecture tuple:
`[app,userId,contextRevision,companyId,sortedBranchIds,owner,resource,id,filters,cursor]`.
ALL requires no branch IDs; SELECTED requires a company and nonempty UUID set.
UUID case and branch sets are canonicalized. Filters are copied, key-sorted and
deep-frozen; malformed/non-JSON, cyclic and sparse-array values are rejected.
Keys separate user, app, company, branch set, context revision, owner, resource,
object, filters and cursor. They confer no authorization; server context/party/
permission/state enforcement remains with identity and each owner service.
