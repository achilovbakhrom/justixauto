## Delivered slice and limits

The ten assigned application leaves implement a private React/Vite Admin
workspace with `/admin/` base and BrowserRouter basename. App instances have
independent in-memory QueryClients. The required injected `SessionBoundary`
surrounds all shell/router content. The default HTML entry deliberately supplies
a boundary returning `null`, as clarified by the coordinator: production auth
is not integrated, and the entry admits no protected content or identity. No
login/recovery/unavailable-state design is invented. The admitted zero-feature
shell also leaves its content region empty. This is not a ready Admin product.

M-A01's fixed sidebar catalog preserves Overview, Companies, Users/access,
Roles/permissions, grouped MFO/Bank/Insurer integrations and Audit in their
observed positions. All eight controls use the integrated shared Button and
are natively disabled: there are no registered feature pages, active links or
contextual document/payment menu entries. T-590 owns actual feature discovery,
validation, routes and session-filtered navigation. The registry imports no
absent features. T-054 and later identity integration own admission, cache
invalidation and the separately gated production auth presentation.

The scoped CSS consumes integrated tokens and reproduces the independent Admin
sidebar/topbar: 248px sidebar, 180px at <=850px, stacked/flex-wrap navigation at
<=580px. Identity text is injected, with no default demo label. There are no
API calls, server authorization claims, local/sessionStorage writes, cookies,
demo identity creation, business tables, business dialogs or mutations.
Row details, table widths and modal interactions remain their feature tasks.

The Vite development/preview middleware serves HTML only within the Admin
prefix for document-compatible GET/HEAD requests after ordinary asset handling.
API paths, missing files/assets and other app prefixes receive non-HTML errors.
The custom HTML transform uses the real index path with the requested deep link
as original URL, so module imports do not resolve relative to an unknown page.
This is local dev/preview behavior, not deployment/edge routing implementation.
API references: [Vite middleware hooks](https://vite.dev/guide/api-plugin.html#configureserver)
and [custom app type](https://vite.dev/config/shared-options.html#apptype).
