## Fixed wire and identity distinctions

The typed declarations' JSON field order defines this membership-v1 wire format.
Each root starts with `format`; catalog/meaning/claim roots carry that identity.
Canonical bytes use UTF-8 JSON without whitespace or omitted fields, explicit
null pointers, empty arrays for empty sets, decimal bounded integers and Go JSON
string escaping with HTML escaping disabled. Digest fields are exactly 64 lowercase
hex characters; SHA-256 covers the entire emitted canonical byte sequence.

Set keys: feature ID, owner-local consumer name, dependency/routing string,
(event type,numeric schema version), (selector ID,numeric version),
(source owner,aggregate type,canonical UUID), and (event UUID,enrollment UUID).
Sorting uses exact UTF-8 bytewise string ordering and numeric revision ordering;
duplicate keys reject, including distinct digests under the same selector key.
Version and generation labels preserve exact nonempty bytes, including spaces
and tabs. Other required references reject blank-only text without normalizing
retained nonblank spelling. UUIDs must be canonical, lowercase and nonzero.

The full catalog and approved owner active/draining/held selection are distinct.
Each finite universe member retains its source verification, disposition and
complete selector identities; multiple consumers can use different selectors
for one stream. A stream manifest must cover every selected consumer exactly
once as included or explicitly excluded, with explicit zero-applicable evidence
for an empty included set. It carries expected old selection, admission roots/
tips, existing typed bootstrap evidence, exact ranges/generation/kind and finite
backlog effects. Existing bootstrap snapshot/no-snapshot/new-empty shape is
preserved without importing projection. Process catch-up has separate evidence.

Requests embed the complete resulting catalog, selection, universe and every
stream/effect manifest, plus request UUID, action, expected head and successor
epoch. Initial requires absent head/epoch 1; later requests require a nonoverflowing
positive signed-bigint successor. Version ordering is not inferred. Empty and
zero-delta requests still retain complete identities. Backlog checks reject
omitted initial recipients, duplicate jobs/enrollments, contradictory event
positions/hashes, out-of-range positions and wrong admission identities.
Late-consumer deltas and actual original bytes still need T-948/owner validation
against retained state; shapes/hashes are not source authority or effect proof.

`MembershipLimits` supplies explicit trusted parsing/resource ceilings for bytes,
JSON values/keys and container depth. No deployment default or business catalog
limit is invented. Preflight checks counts/lengths before copying/output and
bounds raw-token parsing before typed allocation. Limit failure rejects the
whole value; it never truncates, splits, silently omits or approves an empty set.
