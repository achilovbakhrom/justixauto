## Invocation and producer profile

Run the pinned Node executable with `tools/generate-contracts.mjs --config PATH`
to generate, or append `--check` to require byte-identical existing outputs.
The root has no generation script; this task does not pretend one exists.

```json
{
  "version": 1,
  "contracts": [{
    "input": "owner.openapi.json",
    "goOutput": "owner.gen.go",
    "tsOutput": "owner.ts",
    "goPackage": "openapi",
    "owner": "identity",
    "namespace": "Auth"
  }]
}
```

Paths are relative to the config. Input is **JSON-form OpenAPI 3.1**, also valid
YAML 1.2 JSON syntax; a `.yaml` suffix does not enable general YAML parsing.
No general YAML parser/dependency is installed. Producer tasks must retain their
approved schema/security declarations; they must request a profile handoff when
unsupported, rather than removing a constraint to get generation to pass.

Profile 1 supports local acyclic component references, explicitly closed objects,
typed maps without fixed properties, arrays, booleans, null, strings, and integers
with explicit safe JS-number minimum/maximum. Precision-bearing values stay
strings. It supports primitive const/enum, nullable type pairs, required versus
optional fields, item/length bounds, unique arrays, UUID/date/UTC RFC3339 formats,
and a portable ASCII pattern subset validated by both pinned JS and Go engines.
Named component `oneOf` unions require distinct component references and exactly
one matching alternative; no branch is selected merely because it appears first.

`additionalProperties:false` is required on closed objects; typed-map values are
validated recursively. Optional nullable Go fields use
`AuthContractOptional[*T]` with an explicit `Present` bit, preserving omitted
versus null. Named nullable root DTOs wrap `Value`. Go marshal paths
validate constructed DTOs, and decode rejects unknown/missing fields, duplicate
JSON keys, trailing JSON, invalid UTF-8/unpaired surrogates and invalid values.
Go normalizes exact bounded integer JSON forms such as `1.0`/`1e0` without using
floating-point money. TS parses already-decoded unknown values through synchronous
schema adapters and rejects undefined present fields, prototype-bearing objects,
unknown fields, sparse arrays and malformed values. Decimal strings are unchanged.

Schema property/definition order does not affect bytes or source hash. Arrays
(including union alternatives) retain declared order. Headers contain generator
version and canonical source SHA-256, never paths, timestamps or credentials.
Go symbols are prefixed with the explicit namespace so two feature files can
coexist in one owner package; JSON field names and reference identities stay
unchanged. Duplicate namespaces/outputs and emitted symbol collisions fail.
The pinned wrapper selects
Go for RE2 preflight and gofmt; no compiler or module downloads occur.

All configured documents and renderings are checked before output writes.
`--check` never creates/rewrites outputs, and empty configuration fails explicitly.
The tool refuses existing files without its generated header and refuses symlink
output paths/parents. It does not delete orphaned outputs or promise a transaction
across filesystem write failures; output changes remain reviewable Git changes.
Generation writers must remain serialized by the coordinator.

Unsupported schema constructs fail clearly: general YAML, external/recursive refs,
boolean/unspecified schemas, open arbitrary maps, mixed fixed/map properties,
`allOf`/`anyOf`, discriminator, nullable keyword, defaults/coercion, custom formats,
unknown keywords/extensions, floating number DTOs, unbounded/unsafe integers,
inline unions and unsupported regex features. Bounds on canonical revision/money
strings must be stated by their concrete owner schema; generation never guesses
business range, sign, currency, decimal scale or dynamic deployment settings.

## Client and security boundaries

Public `/api/v1/<owner>/...` functions call only the injected T-032 transport.
They validate requests and success/error responses, safely encode path/query
parameters, and preserve the existing three dedicated revision/idempotency
headers. Profile 1 parameters are strings; required JSON bodies use named schema
refs. Multiple success statuses must have the same schema because T-032 cannot
give its adapter the response status. Explicit 204 requires an empty response.
The supported common error statuses remain T-032's exact set.

Internal `/internal/v1/<owner>/...` routes emit **Go methods only** and require a
declared `mutualTLS` security alternative. They never produce a browser-callable
function or internal route string in generated TS. Go methods consume a typed
exchange port carrying destination owner, operation ID, method/path, fresh JSON
bytes/headers and exact declared security alternatives. They validate JSON media
type, status and response DTOs. The injected adapter must bind authenticated
caller identity, destination allowlisting, TLS, bounded IO and those security
requirements; no network/authentication implementation is generated. Transport
failure returns a safe unavailable/unknown-outcome distinction, never an automatic
retry, cancellation receipt or claim that an owner committed.

Approved `__Host-justix_session`, `__Host-justix_challenge` and
`__Host-justix_csrf` cookie security declarations are retained as public endpoint
metadata; the browser's same-origin credential behavior is supplied by T-032.
Security requirements are not authorization checks. Unknown schemes/scopes,
incompatible internal/public security and missing internal mTLS declarations fail.
Owner company/actor/branch/party/state authorization remains server-owned.

Concrete handoffs remain before auth generation/wiring:

1. T-059 must produce an approved concrete schema using supported syntax, or
   request an explicit profile extension for ordinary constructs it needs.
   Neither the empty config nor synthetic fixtures claim auth schema coverage.
2. Response headers (including CSRF rotations), 429, cookie parameters and
   unsupported media/security declarations fail generation. Preserve them in the
   auth contract until the separately assigned shared transport handoff is
   approved and implemented; do not generate a weaker parallel fetch client.
3. The coordinator must assign the concrete config entry when approving generated
   feature outputs. No root script/config activation was inferred from T-641.
4. T-032 supplies parsed JSON values. Raw-byte duplicate-key rejection or numeric
   lexeme validation for browser responses cannot be added by this value adapter;
   any contract requiring it needs a shared transport/decoder handoff. Go's raw
   decoder checks do not establish the same browser raw-byte guarantee.

## Fix cycle 2 — preserve Go methods and adapter contracts

The second QA report reviewed `14eb0c60895c9e47e829338c5bf78b1e873c9fe1`
and reproduced an internal operation named `Error` that renamed the runtime's
required `error.Error()` method. Both prior QA reports and all nine evidence

The generator now rejects collisions with runtime receiver declarations and
actual emitted method selectors before writing outputs. This protects JSON and
omitzero hooks, `error.Error`, the exchange interface, decoder/number/regexp
methods and query methods independently of the public TypeScript symbol checks.
The same preflight also protects stable runtime transport/security/error/optional
field names and operation result fields: renaming both declarations and local
uses could otherwise compile while breaking an independently written adapter.

Coordinator review also caught a lexical limit in scanning the whole rendered
source: enum text such as `x.ReadReceipt(` or `strings.ReadReceipt(` is not a Go
selector. Symbol scanning and namespace rewriting now share exclusions for

generator templates, not a general-purpose Go parser or schema-space proof.

operation positions. Every rejected case preserves both existing Go and TS
output bytes. An accepted internal `ReadReceipt` fixture separately compiles an

selector-looking string values. The internal route remains absent from TS.
