## Verdict

The exact clean commit implements the assigned fixed-precision value package
without changing manifests, contracts, infrastructure, mocks, or another task's
source. `Money` accepts only canonical signed integer strings of at most 38
digits, keeps the selected currency code/exponent/version as identity, performs
exact immutable arithmetic, rejects result overflow and rejects cross-currency,
cross-exponent, and cross-version arithmetic. Its public JSON remains exactly
`{amountMinor,currency}` and accepts no numeric, extra, duplicate, missing, or
trailing JSON content.

Decimal rates are canonical decimal strings with their lexical scale preserved.
The package deliberately assigns no global sign, precision, percent,
basis-point, periodicity, or rounding limit: `http-domain.md` requires each
approved policy to provide its own rate/date/rounding schema. This is the
correct unresolved-policy boundary rather than an invented financial value.
Dates validate real proleptic Gregorian `YYYY-MM-DD` values from year 0001
through 9999. Effective periods include both endpoints and may have an explicit
open end. Missing, zero-value, and out-of-window policies return the generic
zero value plus `POLICY_UNRESOLVED`; no demo/default value appears.
