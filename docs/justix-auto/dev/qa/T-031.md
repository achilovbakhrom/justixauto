## Blocking finding

### QA-T031-01 — a repeated configured URI SAN is admitted

`MTLSResolver.Resolve` collects matching URI SANs in a map keyed by their URI
text. A verified leaf containing the same configured URI SAN twice therefore
collapses to one map entry and authenticates successfully. This violates the
implementation's documented invariant that exactly one configured URI SAN must
identify the peer and weakens the fail-closed handling of certificates with
multiple identity SAN occurrences.

Independent reproduction on an archive of the exact reviewed commit, with the
QA test copied to `pkg/auth/qa_adversarial_test.go`:

```text

  GOCACHE=/private/tmp/justixauto-qa-t031-cache-handshake2 \
  /Users/bakhromachilov/startups/justixauto/docs/justix-auto/dev/local/toolchains/go-1.27.1/bin/go \
  test -race -count=1 -run TestQADuplicateIdenticalURISANFailsClosed ./pkg/auth

--- FAIL: TestQADuplicateIdenticalURISANFailsClosed (0.00s)
    qa_adversarial_test.go:22: duplicate URI SAN occurrence admitted: caller="retail" err=<nil>
FAIL
FAIL    justixauto/pkg/auth    0.551s
```

Required correction: count configured URI SAN occurrences on the verified peer
leaf and reject any count other than one. Preserve the existing rejection of
two distinct configured identities. Add a permanent regression for a duplicated
identical SAN occurrence. Any corrected commit requires fresh exact-commit QA.
