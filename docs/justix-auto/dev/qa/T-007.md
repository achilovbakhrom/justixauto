## Blocking findings

1. **The typed decoder is not version-bound and accepts missing required
   fields.** `DecodeData[T]` only applies `DisallowUnknownFields`; it never
   checks that `T` is the decoder for the envelope's `eventType` and
   `schemaVersion`, and Go's JSON decoder silently leaves absent fields at zero
   values (`pkg/events/envelope.go:299-313`). In the isolated exact-SHA fixture,
   a payload type representing v1 successfully decoded an envelope declaring
   `inventory.reservation.granted.v2`, and `{}` successfully decoded into a
   payload whose `holder` is required. This violates T-007's versioned decoding
   and unknown/missing-field acceptance requirement. A decoder must bind the
   expected event type/version and validate required fields without inventing
   concrete business schemas in this shared package.

2. **Null `companyId` is allowed for every identity event rather than only a
   global identity event.** Metadata validation checks only `owner == identity`
   (`pkg/events/envelope.go:157-163`). The adversarial fixture constructed
   `identity.branch.created.v1` with a null company and it was accepted, even
   though Branch is tenant-owned and the approved envelope contract permits
   null only for global identity events. The shared representation needs an
   enforceable global/tenant scope distinction; syntax under the identity owner
   is insufficient.

3. **The raw-PII guard omits common direct PII keys.** Recursive traversal and
   case normalization work, but the denylist (`pkg/events/envelope.go:230-250`)
   accepted `BirthDate`, `surname`, and `mobile`, including inside an object in
   an array. These are raw personal data, not secure-record references. The task
   requires recursive secret/raw-PII key rejection, so these direct forms must
   be rejected while explicit reference/ID fields remain allowed.
