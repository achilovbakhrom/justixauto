## Finding: a redrive ticket can execute against a different evidence store

**P2, reproducible integrity/isolation failure.** `Redriver.Request` stores both
the request and retained evidence in the opaque `RedriveTicket`
(`pkg/inbox/redrive.go:134–153`). `Execute` never reads the ticket's retained
evidence. It looks up the same evidence UUID through the receiving `Redriver`'s
database (`:163–180`) and invokes that database's restored bytes on the ordinary
path before the result append checks the local action chain (`:188`, `:410–444`).

The independent live regression creates two isolated owner-local PostgreSQL
fixtures. Both deliberately retain the same canonical evidence/request/context
identities but different protected bytes. It appends the authorized
`redrive-request` only in fixture A, then passes A's opaque ticket to fixture B's
`Redriver.Execute`. Fixture B has no matching request action. Actual behavior:

```text
foreign-store ticket entered ordinary path 1 time(s) before final conflict:
inbox: ordinary redrive path failed
ordinary path must not run
inbox: redrive request conflicts with retained evidence
```

The later append correctly detects B's missing request chain, but only after the
ordinary callback has run. That callback is explicitly the external effect/dedup
boundary and can commit independently. Thus an accidental cross-store,
cross-environment or stale-composition ticket can process bytes that were never
the subject of that store's retained authorized request. This violates the
approved requirement to append the request before restoring/submitting bytes,
the task's isolation guarantee and the API comment that authorization is
journaled before protected content is touched. The unexported ticket internals
prevent caller fabrication, but do not prevent a legitimate ticket from being
passed to another `Redriver` instance.

Bind each ticket to its exact owner/store and retained evidence/request. Before
restore or `OrdinaryRedrive.Apply`, fail closed unless the receiving adapter can
prove the exact local `redrive-request` and evidence snapshot represented by the
ticket. Preserve this regression; the ordinary callback count must remain zero
on mismatch. The same binding should be applied consistently to custody release,
although its current local transaction rolls its reference update back when the
request chain is absent. No application fix was attempted by QA.

[overlay.json](T-015/overlay.json).
