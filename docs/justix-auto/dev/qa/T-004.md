## Blocking finding

The shared test command silently omits an individual workspace whose
`vitest.config.ts` is missing whenever at least one other project config remains.
The fixture contained an app and a shared package, each with one passing test.
After renaming only the app config, `npm run test:unit` exited 0 and reported one
file/test passed; the app test was never run. Evidence:
`/private/tmp/justixauto-qa-t004-r2.ykxqYp/missing-one-config.log`.

This defeats the strict workspace verification contract: a later app task can
accidentally omit or misname its Vitest config and still receive a green root test
result. The zero-project guard is insufficient once any valid project exists.
The root test setup must compare discovered npm workspaces with required project
configs, or otherwise fail when an expected workspace config is absent. Re-run
exact-commit QA after the correction.
