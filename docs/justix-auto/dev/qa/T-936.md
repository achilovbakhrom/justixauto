## Blocking finding: returned Promise from a method getter escapes rejection handling

`web/packages/api/src/client.ts:194–195` captures `Reflect.get(receiver, name)`
and immediately throws a new Missing binding error when the result is not a
function. A getter returning `Promise.reject(new Error(secretDiagnostic))`
therefore loses its native Promise before `synchronous` or `disposePromise`
can observe it. The outer request catch receives only the replacement error.

The [independent actual-source probe](T-936/probe.mjs) reproduces this for all
four capture sites: success `schema.parse`, declared error `schema.parse`,
`authExchange.prepare` and `authExchange.accept`. Both local and cross-realm
native Promises produce `invalid-request` and zero fetches, **but each emits one
unhandledRejection carrying the original synthetic private diagnostic**. The
eight reproduced cases and boolean diagnostic observations are in
[probe-output.json](T-936/probe-output.json). No hostile Promise subclass,
species, proxy, thenable assimilation or independent unreturned work is involved.
This is an invalid binding that must fail closed without leaving its returned
native rejection unobserved, consistent with the task's synchronous callback and
payload-free failure requirements.

Correct method capture so a supported returned native Promise is disposed before
the fixed binding failure. Preserve synchronous callable getters, class/prototype
methods, receiver binding and capture-once behavior. Do not read or invoke an
arbitrary thenable's `then`. Add regressions for these four getter positions,
local/cross-realm rejected returns and the existing valid getter cases. Expected
behavior remains `invalid-request`, no prepare/fetch/sink side effects, and **zero
global unhandled rejections**. QA made no application fix. This requires a new
exact-commit check before integration.
