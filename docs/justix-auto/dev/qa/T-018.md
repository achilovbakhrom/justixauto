## Finding requiring correction

**P2 — Released scheduling leases produce a database conversion error instead
of `ErrLeaseLost`.** `pkg/commands/worker.go:153` evaluates
`lease_owner=?::uuid AND lease_until>clock_timestamp()` and scans into `bool`.
Both columns become SQL NULL after successful `WithClaim` or `Retry`. Reusing
the retained claim then returns:

```text
sql: Scan error on column index 0, name "?column?": sql/driver: couldn't convert <nil> (<nil>) into type bool
```

The independent probe commits a real local effect/step, injects loss of the
commit reply, and retries the same claim. Its check for `ErrLeaseLost` fails.
The scheduling fence still prevents duplicate effects, but a normal recovery
condition is misclassified as a database failure. Consumers using the exported
sentinel cannot choose their intended stale-claim recovery path. The same SQL
path is shared by `Retry`. Handle an absent lease as a false live-fence result,
preserve genuine storage errors, and add regression checks for both methods
after lease release. Do not change schema or relax fencing to repair this.

Reproduction: `T-018/adversarial_test.go.txt`, subtest
`unknown local completion commit recovered by retained step`; loaded using
`T-018/overlay.json`. This adds a test through Go overlay without modifying the
reviewed package. It tests both real rollback plus lost reply and real commit
plus lost reply. The rollback case converges; the committed case exposes the
finding above.

## Independent evidence and boundaries

Passing probes verify a lease expiring while blocked on a row lock cannot run
local effects; eight concurrent attention scanners commit one alert intent;
failed alert persistence rolls back its flag/effect; year-old active leases
remain undecided/nonterminal; company and kind filters run before authorization
callbacks; denied resume preserves revision; malformed stored step results fail
closed; runtime credentials cannot delete operation history, mutate a completed
step, or change company ownership.

At the coordinator's request, a separate probe holds `WithClaim` inside its
local callback until the wall-clock lease expires. A concurrent `Claim` returns
no work because the row is locked. The original local effect then commits and
a subsequent claim obtains a new token. Thus T018 checks lease validity before
the callback and serializes completion with its row lock; it does **not** enforce
a wall-clock lease deadline at final commit. This is recorded as a boundary,
not a second finding: the approved T018 contract does not require that stricter
deadline. Long remote requests belong outside this local callback. A later
dispatch contract's stronger fence is not retroactively claimed here.
