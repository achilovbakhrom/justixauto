## Blocking findings

1. **P1 — implicit default function privileges evade readiness.**
   `pkg/persistence/check.go:299` inspects existing `pg_default_acl` rows only.
   On the pinned PostgreSQL fixture, `ALTER DEFAULT PRIVILEGES FOR ROLE
   justix_identity GRANT EXECUTE ON FUNCTIONS TO PUBLIC` restores the implicit
   default and leaves **zero owner function-default rows**. `Check` incorrectly
   succeeds. A subsequently created ordinary owner-local function has effective
   runtime EXECUTE, and calling it as `justix_identity_runtime` returns `1`.
   This contradicts P4's requirement that new objects cannot silently inherit
   broader access. The probe removes its synthetic function, restores denied
   defaults and verifies healthy readiness. Account for the effective built-in
   defaults as well as explicit global/schema ACL additions; test other relevant
   object defaults without granting a permissive fallback.

2. **P2 — a nonexecuting immutable guard is accepted.**
   `pkg/persistence/check.go:257` selects name/function/type/enabled mode and
   owner properties but omits the trigger predicate. Recreating
   `owner_migrations.artifacts.artifacts_immutable` with the identical name,
   function, timing, event type and statement granularity plus `WHEN(false)`
   passes `Check`. Ordinary migration-owner `UPDATE` then bypasses the immutable
   guard; the demonstration rolls back its UPDATE. The original guard is restored
   and readiness succeeds again. Compare the required guard's execution metadata,
   including its unconditional predicate, rather than claiming that a matching
   name and enabled flag establish the required guard. This finding does not
   demand function-body hashing or tamper-proof protection against trusted DDL
   administrators. The existing explicit replica-only guard rejection passed.

3. **P2 — manifest decoding accepts ambiguous or malformed raw identities.**
   `pkg/persistence/profile.go:376` uses the ordinary JSON decoder before any
   duplicate-key/raw-Unicode validation. With the exact original malformed bytes
   hashed into the trusted profile, each of these manifests passes `VerifyFiles`:
   an earlier `owner: inventory` overwritten by `owner: identity`; an earlier owner
   value containing raw invalid UTF-8 byte `ff` overwritten by the valid owner;
   and an earlier lone-surrogate `\\ud800` value overwritten by the valid owner.
   A matching byte digest establishes identity of bytes, not validity of their
   format. Reject duplicate decoded keys and malformed raw Unicode in every
   field/key before decoder overwrites or replacement can discard the evidence.
   Clean manifests pass; unknown nested fields and trailing scalar data reject.
