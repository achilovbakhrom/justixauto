## P2 — readiness accepts excessive effective runtime privileges

Location: `services/identity/adapter/postgres/unit_of_work.go`, function
`check` (lines 70–104 privilege predicates).

The runtime readiness query does not cover all forbidden privilege surfaces.
Starting from a valid explicitly installed Identity store, each grant below
independently leaves **Check=nil, Run=nil, factory calls=1, callback=true**:

| Probe | Excess grant |
|---|---|
| table_maintain | MAINTAIN on eventstore.events |
| marker_column_insert | INSERT(singleton,owner_service,mechanics_version) on identity_mechanics.compatibility |
| ledger_column_insert | INSERT(version,dirty) on public.schema_migrations |
| marker_column_references | REFERENCES(singleton) on identity_mechanics.compatibility |
| ledger_column_references | REFERENCES(version) on public.schema_migrations |
| table_references | REFERENCES on eventstore.events |
| column_references | REFERENCES(event_id) on eventstore.events |
| database_create | CREATE on database justix_identity |

These are actual successful PostgreSQL GRANT operations, followed by calls
through the reviewed production adapter; no production source was overlaid.
The column INSERT grant on the migration ledger permits inserting additional
migration-version records. Database CREATE permits runtime-owned schema DDL.
MAINTAIN and REFERENCES also exceed the intended narrow technical role;
T-008's installation guard already explicitly rejects table REFERENCES.
The current query checks column UPDATE but omits INSERT/REFERENCES on the
read-only marker/ledger, omits REFERENCES/MAINTAIN table privileges, and does
not inspect database CREATE.

This task does not introduce these grants itself. The defect is that its
explicit fail-closed readiness contract does not detect them before feature
construction/execution. Fix the bounded privilege validation, including
equivalent reachable-role grants and PostgreSQL 18 privilege surfaces, and
retain the intended allowed event/work scheduling grants. Do not silently
revoke grants or expand migration/application scope in the readiness check.
A new exact source commit requires independent QA.
