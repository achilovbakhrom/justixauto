## Findings

### 1. GET session cannot represent the required invalid-request outcome

Severity: blocking contract mismatch.

The adopted auth contract rejects unknown query parameters on every auth route
and maps an unknown field/query/header or wrong representation to
`400 INVALID_REQUEST` (`state/drafts/contracts/auth.md`, lines 79 and 204-208).
The `GET /api/v1/identity/session` response map contains only 200, 401, 429 and
503 (`auth.yaml`, lines 324-332). A raw request with an unknown query parameter
therefore has a required server outcome which the generated exact status/error
map cannot accept; it would be classified as an unexpected status rather than a
typed rejection.

The current test iterates only statuses which are already declared
(`identity_auth_test.go`, lines 130-168); it never asserts the exact per-route
status set. The direct probe

```sh
jq -e '.paths["/api/v1/identity/session"].get.responses | has("400")' \
  services/identity/contracts/openapi/auth.yaml
```

returns `false` with exit 1.

Required correction: declare the closed `400 InvalidRequestError` response with
the adopted no-store metadata and add an exact response-matrix regression/unknown
query fixture so omission cannot pass again.

### 2. Enrollment path ID weakens the canonical ID contract

Severity: blocking schema/validator mismatch.

T-058 defines every `ID` as a canonical lower-case nonzero UUID, and the adopted
semantic handoff repeats that rule. The enrollment confirmation `{id}` parameter
is instead declared only as `{"type":"string","format":"uuid"}`
(`auth.yaml`, line 449). The current generator's UUID format validators are
case-insensitive and accept the all-zero UUID (`tools/generate-contracts.mjs`,
lines 416 and 538). Because this inline parameter does not carry the lower-case
pattern or a visible nonzero semantic requirement, the concrete operation schema
does not preserve the approved ID boundary.

The T-059 test checks only the CSRF parameter and does not inspect the path ID
schema (`identity_auth_test.go`, lines 111-128); the fixture catalog has no
uppercase/zero enrollment-path case.

Required correction: encode the canonical lower-case constraint and explicit
nonzero semantic handoff for this path parameter, then add negative parameter
fixtures/tests proving uppercase and zero IDs are rejected before owner use.
