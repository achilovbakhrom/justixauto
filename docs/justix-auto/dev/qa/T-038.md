## P2 — non-document requests receive successful application HTML

At `web/apps/financing/vite.config.ts:24`, accepting `*/*` is treated as enough
evidence to serve the document fallback. Fetch metadata is ignored. Thus missing
extensionless resources outside the explicitly reserved directories are returned
as `200 text/html` containing `finance-root`, in both development and preview.

Reproduction against either QA server (4482 dev, 4483 preview):

```sh
curl -i http://127.0.0.1:4482/finance/missing-resource \
  -H 'Accept: */*' -H 'Sec-Fetch-Dest: script' \
  -H 'Sec-Fetch-Mode: no-cors'
```

The same happens with `Sec-Fetch-Dest: empty` / `Sec-Fetch-Mode: cors`.
An actual Chromium page executing `fetch('/finance/missing-resource')`, with its
automatic browser headers and no forged request headers, independently returned
the same 200 HTML in both modes. Expected: non-HTML 404 for these resource
requests; ordinary document navigation to Financing deep links remains 200.
The developer's JSON-only non-document test does not exercise the normal fetch
default. This is a local development/preview routing defect, not a demonstrated
production authorization or data exposure issue.

Correct document-intent classification before serving fallback and add coverage
for actual fetch/script destinations, while preserving valid GET/HEAD document
deep links and existing asset delivery. QA made no implementation fix. The
runner records ten failed assertions covering this one defect (status and body
assertions, both modes, and real browser fetches).

`web/apps/realization/vite.config.ts:24`, confirmed on main
`2dd6cf4fbeb5093c5b683d0f99724d327870235a` as well as the reviewed worktree.
