## Remaining finding

**P2 — an accepted internal operation name still produces uncompilable Go.**
Changing only the synthetic internal GET operation ID from `ReadInternal` to
`Error` makes generation exit 0 and change both output files. Actual Go
compilation then fails repeatedly with:

```text
FixtureContractFailure does not implement error (missing method Error)
```

`tools/generate-contracts.mjs:232` checks public operations against the TS
reserved names, which include `Error`; internal operations skip that check.
The Go namespace pass at lines 522–546 includes every operation ID and rewrites
the runtime's required `ContractFailure.Error()` method at line 475 into
`FixtureError()`. The type consequently loses its Go `error` implementation.
This is another case of the original emitted-symbol finding, despite the three
original component names now being rejected correctly.

Reject this collision before any output changes, or preserve required interface
method identifiers during symbol-aware generation. Add an internal-operation
regression that requires either working Go/TS output or explicit rejection with
all prior outputs byte-identical. Protect the complete generated method contract,
not only public operation names. No schema/security constraint should be weakened.

The independent runnable producer is [independent.py](T-640-r2/independent.py).
[independent.json](T-640-r2/independent.json) records the exact input variation,
generator success, changed-output observation and compiler diagnostics under
`internal-operation Error`. Its `temporary_root` retains the generated fixture.
The runner intentionally records failed expectations in JSON rather than
equating its own exit status with GREEN: **32 of 33 groups pass**.
