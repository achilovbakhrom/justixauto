## Verified behavior

Populated legacy and custody installation preserves prior rows, marker values,
route bytes, function definitions/owners/OIDs/ACLs, table/column ACLs and old
trigger attachments. The bootstrap FK adds only its necessary two internal
admission-parent triggers. No checkpoint is inferred from retained history.
Revision-4 marker is immutable and runtime SELECT-only. Explicit installation
requires the migration owner, exact prior identities and supplied artifact hash;
wrong lineage/owner/runtime, malformed evidence, reinstall and incompatible
privileges fail atomically. Concurrent installers have one winner; an active
writer causes the specified bounded migration lock failure and full rollback.

Direct, PUBLIC, column, grant-option, default and two-hop NOINHERIT access are
tested. Independent probes add reachable inbox REFERENCES, mode column INSERT,
schema grant delegation, default table SELECT delegation and default function
execution: each aborts installation with exact preimage/catalog retention.
Cross-owner runtime access is denied. Existing narrow work grants remain intact.

Bootstrap initialization uses exact authorized-high-water shape or explicit
new-empty evidence, with no reset or conflicting request mutation. Custody
requires matching local root admission; both projection and process retain
non-UUID labels. Independent probes also preserve leading/trailing whitespace
of a nonempty existing label and reject trimmed labels, different scope,
purpose, authority, contract and digest. These compare evidence, not real
business authorization. Checkpoints require position/revision +1 and matching
consumer/event/hash inbox evidence. Missing/wrong consumer/hash and numeric
overflow roll back. Concurrent checkpoint changes, callback failure, panic,
cancellation and both actual-commit/actual-rollback lost replies retain their
specified authoritative outcomes without callback retry.

Gap evidence survives a fresh transaction after the effect/inbox rollback.
Cross-bootstrap identity, duplicate request/event identities, out-of-range
attempt intervals, premature resolution, stale holds, cross-gap parents,
branching successors and changes after resolution are rejected. Independent
probes confirm failures leave the original root evidence alone. Source history,
snapshot rows and authorization references here are synthetic fixtures.

Prepared fences bind actual live ReadCommitted server transaction/backend/nonce,
reject pools, committer-shaped pools, foreign/ended transactions and wrong
isolation, and require exact owner/key/mode coverage. Tests observe source before
catalog, sorted receiver keys, sorted encoded generation/guard keys, shared
writer coexistence, exclusive contention and catalog phantom prevention.
Duplicate requests merge to strongest mode; second preparation/late upgrades
fail. Missing coverage suppresses effects and cancellation releases locks.
Independent savepoint rollback invalidates the old capability and releases its
locks; a later preparation has a new nonce and cannot revive the old handle.

The initial independent test incorrectly required rejection of a real read-only
ReadCommitted transaction. PostgreSQL permits its transaction advisory locks,
and the approved contract does not forbid this mode. The initial failure is
preserved in `adversarial-initial.txt`. The corrected probe verifies actual
read-only mode, valid same-transaction capability, SQLSTATE 25006 on a write,
and foreign-owner/repeated-preparation rejection. All six groups then pass on
the unchanged reviewed commit. This was a QA expectation correction, not an
application fix.
