## What was demonstrated

The independently rerun baseline covers actual append/writer rollback and
commit, immutable per-recipient bytes/IDs/routes, concurrent SKIP LOCKED claims,
original legacy/additive legacy/custody mode rejection, missing/foreign/expired
leases, post-row-lock database-clock completion, explicit empty plans and holds.
Actual SQL commit and rollback followed by lost replies reconcile distinct
durable claim/completion outcomes. A claimed row is visible and lockable from
another connection during network work, establishing that the publisher callback
does not retain the claim transaction. Persisted attempts drive 1s–60s bounded
exponential jitter; a retry threshold does not complete or cancel business work.

Real RabbitMQ tests demonstrate mandatory return plus positive confirm leaves
that recipient unsent while another succeeds; a dropped genuine broker ACK and
restart preserve original bytes and produce a same-ID duplicate on retry;
forbidden routing closes the channel; quorum overflow produces an actual NACK.
Correlation units exercise simultaneously readable return/ACK notifications,
wrong identities/sequence/bytes, cancellation and channel loss. Source inspection
of pinned amqp091-go v1.14.0 `channel.go` dispatch and Confirm documentation
supports the return-before-confirm buffer-drain assumption. The publisher uses
one outstanding mandatory persistent message per dedicated nonrecovering channel.

Additional independent real PostgreSQL/RabbitMQ probes establish:

- Two valid real confirmation receipts cannot be swapped across destinations.
  Mutating a byte slice returned by the public accessor cannot alter broker bytes;
  duplicate completion cannot reset confirmed history.
- A hold committed while MarkSent waits on its row defeats completion after the
  lock releases, even though RabbitMQ already accepted the publication. Retry
  also cannot clear that hold.
- Lost replies during Retry distinguish actual commit (pending) from rollback
  (leased), with no sent state in either case.
- A canceled completion cannot consume a valid real receipt; a later valid
  completion can use that receipt while its lease is still current.
- PUBLIC column REFERENCES, message MAINTAIN, schema CREATE and missing message
  SELECT fail before incrementing attempts or calling the publisher.
- An unknown Claim remains unpublishable after reconciliation observes its
  committed lease; the real publisher returns ErrInvalidRecord and the broker
  queue remains empty.
- Retry preserves the retained destination, route and admission IDs, event ID
  and bytes while acquiring a fresh attempt token.
