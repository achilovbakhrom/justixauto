## Resolution of prior findings

- Recovery proof now has an explicitly **unapproved** contract delta, referred
  to the existing T-058 auth contract task. A separate restricted cookie and
  CSRF token precede the request; the proof route binds token, browser challenge,
  purpose, user and security version. Its private grant authorizes only password
  reset. Completion retains the baseline request fields and consumes token and
  exact factor counter/code with the credential change and revocation in one
  identity transaction. Failed password validation consumes nothing; changed
  security version, consumed proof and concurrent completion fail closed. A lost
  reply remains an unknown outcome followed by login or fresh recovery rather
  than a false rollback claim or generic authentication command receipt.
- Recovery-code authority is now explicit: password reset only, with no MFA
  removal or re-enrollment. Factor-loss recovery remains separately gated. The
  user can approve or reject this limited scope without an implied bypass.
- Delivery now distinguishes digest-only authorization records from recoverable
  authenticated ciphertext in a short-lived identity-private delivery job.
  Authority and job creation are atomic; retry reuses the same token, rechecks
  current authority/expiry, and permits duplicate emails after a lost send
  acknowledgement without claiming exactly-once delivery. Confirmation,
  revocation and expiry destroy the ciphertext. Generic events/outbox payloads
  remain secret-free. Manual copy/paste and a fixed public URL satisfy the
  proposal's prohibition on token-bearing URLs; recovery remains bound to its
  initiating browser.
- Invitations explicitly accept only already credentialed identities with
  independently verified matching email. Pending-user credential setup and
  initial verification remain gated. The described atomic acceptance checks
  invitation/company/email binding, pending status, expiry and revocation before
  one-use consumption and authorized membership creation. It introduces no
  public registration, account linking or role escalation.
- TOTP wording now distinguishes browser enrollment disclosure from transient
  server decryption for verification. Encryption at rest and no logging remain.

No remaining defect in those bounded findings prevents presenting this draft
for review. These are proposal-level protocol checks, not implementation tests.
