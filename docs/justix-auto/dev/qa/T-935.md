## Harness correction and delivery limits

The initial mutation oracle operated on the pre-encoding JavaScript string.
Inserting a character between an emoji's surrogate units produced
`"\ud83dx\ude00"`; TextEncoder replaced the lone units with U+FFFD **before**
the product decoder received bytes. The product correctly accepted that valid
encoded string. QA corrected only the oracle to parse the actual bytes and
retained both initial diagnostics in commands.txt. This was not a decoder
defect, and malformed raw UTF-8/escaped-surrogate rejection remains tested.

This leaf is a synchronous parsing utility, not a Fetch/session integration.
T-936 must capture client limits once, bound/cancel streamed body reads and wire
this decoder before status-specific structural/semantic/metadata acceptance.
The optional trusted limits argument supplies that future composition; it does
not accept limits from response headers. No cookie, retry, authorization,
one-time-secret handling or production policy is implemented here. Endpoint
schemas remain responsible for string money/revisions and feature semantics;
safe integer parsing does not authorize numeric substitution for those strings.
T-002 remains unaccepted. No React component changed, so no browser visual or
React Doctor gate applies to this exact task.
