## Blocking finding: binding errors can preserve protected state and stale CSRF

`web/packages/api/src/authEpoch.ts:233–237` accepts `kind:'unchanged'` for any
validated HTTP error with no CSRF metadata, except logout. It preserves session,
restricted state, view and token. Only `AUTH_OUTCOME_UNKNOWN` has a mandatory
error-code-specific invalidation guard earlier in the acceptance path.

The approved [P4 matrix](../../state/drafts/contracts/auth-transport-compatibility.md#p4-narrow-header-wire-refinement-and-browser-limits)
states: **“CSRF/session errors invalidate usable binding.”** P5 requires hidden
protected content and cleared token on invalidation, followed by explicit
reacquisition. T-058's [endpoint/error contract](../../state/drafts/contracts/auth.md#4-http-transport-and-endpoint-matrix)
requires a live full session for challenge creation and identifies
`CSRF_REJECTED`, `SESSION_EXPIRED` and `SESSION_REQUIRED` as binding errors.

The [independent probe](T-944/probe.mjs) uses the actual shared client and
controller. It first acquires authenticated context, then calls the exact
`POST /api/v1/identity/session/mfa/challenges` route with expected state
`authenticated`. A synthetic status-specific parser verifies the tested error
code before acceptance; headers meet the declared forbidden-CSRF error rule.
For each of **403 CSRF_REJECTED, 401 SESSION_EXPIRED and 401 SESSION_REQUIRED**,
the supported classifier decision `{kind:'unchanged'}` produces:

- `accepted`, epoch 0, with phase still `authenticated`;
- `withSession` still exposes the old protected context;
- a subsequent unsafe challenge request dispatches using the old token, with no
  intervening GET acquisition.

All three observations are retained under `findings` in
[probe-output.json](T-944/probe-output.json). The current decision union has no
ordinary binding-invalidation decision: `uncertain` is restricted to 503
AUTH_OUTCOME_UNKNOWN and `clear` to successful logout/recovery 204. An adapter
would have to throw or reenter controller invalidation to enforce this contract.
That is not an explicit, safely constrained binding-error transition.

Add a bounded path that invalidates usable memory on the approved binding errors
and prevents `unchanged` from retaining authority for those cases. Preserve
anonymous GET SESSION_REQUIRED acquisition, ordinary non-binding rejections such
as throttling, and the distinction between a known error and unknown commit.
Verify that protected/restricted/one-time state and old token become unavailable,
the in-flight ticket retains exclusion until settlement, a second unsafe request
cannot reuse the token, and only explicit serialized GET reacquisition restores a
binding. No automatic retry or acquisition. New exact-commit QA is required.
