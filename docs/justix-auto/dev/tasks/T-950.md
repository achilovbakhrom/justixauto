## Owned deliverable

Adapt Gaze's aggregate-base idea into a pure, generic lifecycle in `pkg/events`.
The type owns validated identity/type, initial/restored revision, current state
and command-local pending changes. Raising a change calculates the exact next
revision, applies a pure transition and publishes the new state/revision/change
only when that transition succeeds.

A validated `NewChange` constructor is part of this task so T-951 can adapt
stored replay metadata without exposing mutable fields. It rejects revision zero,
zero time and non-zero UTC offsets, and normalizes accepted zero-offset times to
`time.UTC`. Generic state/event values are explicitly immutable-by-contract;
owners must use immutable values and pure transitions because Go cannot deep-copy
arbitrary maps, slices or pointers.

No clearing/commit method is allowed: aggregate instances are command-scoped and
discarded after the outer UOW. This prevents an unknown commit result from being
represented as a successful in-memory commit. No SQL, GORM, broker, snapshot,
serializer registry, global bus or business event belongs here.

## Acceptance

- New aggregates start with expected/current revision zero; restored aggregates
  preserve their validated base revision.
- Multiple raises are contiguous and ordered from `base+1`.
- A rejected transition changes no state, revision or pending collection.
- Invalid canonical UUID, aggregate type, occurrence time or transition fails closed.
- Nil receiver accessors return zero values, `Pending` returns nil and `Raise`
  returns the aggregate sentinel; transition errors retain identity and revision
  overflow remains detectable with `errors.Is`.
- Pending slices are defensive copies; event/state immutability remains the
  responsibility of owner value types and is documented explicitly.
