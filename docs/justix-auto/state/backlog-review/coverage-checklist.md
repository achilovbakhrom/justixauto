# JustixAuto — PO backlog coverage checklist

Date: 2026-09-13. Read-only coverage review of target `docs/justix-auto/{business-logic,architecture,open-decisions,mock-map}.md` and `contracts/http-domain.md`.
This is a review aid, not backlog approval, a release commitment, PM tasks or implementation evidence. Coordinator owns the architecture approval record; source architecture/appendix headers still said PROPOSED at inspection and must not override the scoped recorded user decision.

## Required user-value journeys

- [ ] **Enter the correct workspace securely.** First provider Admin creates company + new user + credentials + global company-admin role + membership atomically; activation has a reason; the provider signs into its separate app. Include duplicate-login/company rollback, no silent existing-user reset/link, MFA/session/CSRF/bootstrap and safe recovery. A form scaffold alone does not finish this journey. Refs M-A02, M-F01/M-I01; OD-12 and OD-05/11 affected policies.
- [ ] **Manage company access without changing identity semantics.** User roles are global and identical across memberships; membership contains company/branch access, never a role. Grant, revoke and regrant membership; edit role permissions; suspend/restore users; revoke sessions; protect system roles, self-access and the last effective MFA-enabled platform administrator. Revoking one membership preserves all others. Audit excludes credentials. Refs M-A03–05.
- [ ] **Choose context and maintain organizations.** Company/branch picker is separate from editing company details; company switch resets branch scope to ALL and discards late previous-context responses. Company creation does not switch context or create stock. Edit preserves stable IDs/historical snapshots. Country supports free input; changing it clears region. Retail-only setup cannot silently require B2B partnership. Refs M-R01/M-R12/M-A01–02; OD-03.
- [ ] **Create, link and unlink a branch warehouse.** Support standalone company warehouse, branch without warehouse, branch + create/link warehouse, later attach/create, and explicit detach. One primary warehouse per active branch; company and warehouse revisions/ownership checked. Pending/error/recovery must be visible, lifecycle conflicts rejected; unlink preserves warehouse, capacity and all stock. Do not model unlink as warehouse deletion or only cover branch-creation setup. Refs M-R05/M-R12.
- [ ] **Receive stock with known VINs.** One command atomically creates batch, all VIN units and placements and updates capacity, or rolls everything back. Validate syntax, duplicate VINs within input and globally, exact model/specification and warehouse capacity. Existing canonical VIN follows authorized move/shipment receipt with stable ID, never duplicate creation. Refs M-R05/M-R06; HTTP receipt `stock.mode=identified`.
- [ ] **Receive stock before VIN identification.** Accept homogeneous positive quantity without fake units; display unidentified stock separately. Later add fewer VINs than outstanding quantity while each identification command is atomic; identified count rises and unidentified falls with zero occupied delta. Block reservation, sale, order allocation and shipment of unidentified stock. Quantity correction is audited delta, not arbitrary confirmed-count edit. Refs M-R05/M-R06; OD-06 correction/evidence gate.
- [ ] **Keep one vehicle and accurate capacity across views.** Occupied = placed units + active unidentified quantity; reject capacity below occupied; same-company move frees source and occupies destination atomically without title change. Distinguish owner/custodian/placement/customs/damage/reservation. Include concurrent receipt/move/capacity and retail-versus-wholesale reservation contention. Nine specification inputs, dependent make/model/variant fields and separate ordered exterior/interior photos remain explicit. OD-02 gates only default Vehicles projection; OD-06 gates route evidence.
- [ ] **Form and end B2B relationships safely.** Incoming accept/decline, outgoing withdrawal and active end are different actions/actors. Before active relationship show permitted profile only; ending denies new business but preserves existing contractual records. Offer version/audience/publication has no reservation side effect. Refs M-R02/M-R04/M-R07; OD-04 partner-warehouse/resale extras remain gated.
- [ ] **Negotiate and fulfill procurement, not only demo direct order.** RFQ → quotation versions → accept exact immutable quotation + order; direct published-offer order separately awaits supplier confirmation. Cover factory-before-VIN, foreign direct, in-transit and local routes; accepted changes via mutual addenda; concrete-VIN atomic reservation; shipment milestones, customs and receipt accept/reject with mandatory rejection reason. Cancellation must await exact reservation release, never timeout-release. Refs M-R03/M-R08; OD-04/06/13 gate unresolved transitions and missing HTML states, not the whole commercial model.
- [ ] **Record and review external payments.** B2B buyer submits evidence; seller financial actor accepts/rejects with proper confirmation/reason, schedule and partial-payment visibility. Retail vehicle/registration invoices remain retail-owned; client payments to bank/MFO are not seller receipts. Correct owner/card entry and history; no removed “От партнёров” billing tab. No editable paid dropdown or implied transfer. Refs M-R03/M-R08/M-R11; paid cancellation, corrections/overpayment allocation and registration rules remain scoped gates.
- [ ] **Convert CRM work into one reserved sale.** Company-local natural-person customer; lead source/assignee/contact history, stage progression/loss reason, next task/completion; manual or eligible-lead sale requires existing customer and available VIN. Show reservation pending/failure without duplicate active sale or lead conversion; successful delivery alone wins lead and updates listing. Listing publication edits no VIN facts. Refs M-R07/M-R08/M-R10; backward/reopen/skip policies unresolved.
- [ ] **Preserve cash and own-installment progression with explicit gates.** Cash includes separate vehicle payment, registration invoice/evidence/facts and delivery. Own installment includes underwriting decision, first contribution, contract, registration and later servicing history; delivery does not close the receivable. OD-07/08/09 block unsupported production tariff/coverage/arithmetic/servicing transitions; do not invent a rule or silently omit the eventual user journey. Refs M-R08/M-R09/M-R11.
- [ ] **Complete seller ↔ financier review round trip.** Provider owns versioned draft/published/withdrawn programs. Seller chooses bank/MFO → organization → program, sees frontend preview, saves draft then explicitly confirms submission. Changing provider clears program/calculation. Addressed provider takes review, requests information, sends immutable terms or declines; seller responds, counters or agrees exact terms. Drafts hidden on all provider surfaces, including counts/history/downloads; sent snapshots survive later edits. Show both parties' state labels and one shared application/history. Refs M-R13/M-F01–03; no invented one-active-finance-application constraint.
- [ ] **Complete post-agreement document exchange.** Provider requests; seller uploads version; provider explicitly accepts or returns with note; seller replaces with a new immutable version. Provider cancellation with reason is supported only from requested/changes; review cancellation is unresolved. Version/actor/history and addressed-party security remain visible. Agreed/accepted does not mean signature, title, funding, servicing or handover. Refs M-R13/M-F04; OD-01.
- [ ] **Complete seller ↔ insurer underwriting.** Own-company, undelivered, own-installment sale only; one application per company+sale across all states. Draft save and send distinct; addressed insurer takes/reviews, asks for information, approves/declines with note; seller response note required. Preserve immutable snapshot, additive response versions and common history; reject cash/foreign/completed sale and seller impersonation. Decision produces no policy, coverage, money or delivery. Refs M-R14/M-I01–02; OD-08.
- [ ] **Handle documents as actual secure files.** Upload intent → upload → completion/scan pending → exact clean immutable version → owner-authorized binding/use; rejected scan, scanner outage, interrupted upload, expired capability and forbidden download have usable recovery. Scan-clean is not domain acceptance, signature or paid proof. New upload never overwrites prior bytes/history; sensitive download reauthorizes/MFA. Ref each contextual owner surface; OD-10 production data/retention/limits.

## Acceptance required for every applicable backlog item

- [ ] Actor, company/counterparty, visible entry, entity/owner, source references, state sequence, success receipt/history and observable user outcome; FE items carry the exact four-HTML app/file/navigation plus M-ID and required fixture/state, not Figma or retired screen IDs.
- [ ] Read states: loading, empty, filter-empty, read error, session expired, forbidden and hidden/not-found; scope before counts/pagination, no leaked drafts or foreign VIN details.
- [ ] Mutation states: field validation with preserved nonsecret input, review/confirmation when applicable, cancel-before-submit without writes, processing/no double submit, durable pending, success/reopen, permission/MFA/policy denial, stale revision requiring explicit refresh/review, invariant conflict and network-unknown outcome.
- [ ] Identical-key retry and receipt recovery after reload never duplicate writes; unknown outcome/receipt-not-found is not proof of failure. Closing a dialog is not durable cancellation. Context switch/sign-out clears client views but does not abandon server recovery. Projection lag must not undo a committed receipt or optimistically alter authoritative stock.
- [ ] Batch endpoints currently use all-or-none semantics. Distinguish partial **identification across separate commands** from per-item partial command success. Any proposed partial-result endpoint requires explicit contract approval and per-item outcomes, not invented UI behavior.
- [ ] Backend authorization tests and multi-party E2E checks include normal negative paths, live revoked access, cross-company/branch isolation and concurrent/stale writes. Include replay/crash recovery, immutable snapshots, document versions and money precision when relevant; demo tests are not production QA.
- [ ] Financial calculation is frontend-fast but server-recomputed against approved named/versioned policy; integer minor-unit strings, exact schedule closure/currency and no silent FX or demo fallback. Missing policy is explicitly unavailable, not a made-up tariff.
- [ ] Missing auth/MFA, pending-branch, scan interruption, stale/permission, projection lag and wholesale HTML states get captured evidence or user-confirmed supplements before their FE parity readiness. Current four HTML references remain authority; do not demand Figma.
