## Audit when PM files arrive

- [ ] **Coverage and size:** every active B-ID/acceptance clause maps to task(s), including gated portions; Icebox has no execution tasks. Each task is independently testable, ≤ half a dev-day, with explicit owned files, branch, tests and valid acyclic dependencies. Large multi-owner journeys are split at contract/transaction boundaries without omitting end-to-end wiring.
- [ ] **Seven-owner runtime:** identity, inventory, commerce, retail, financing, insurance and documents each have API/projection/worker composition, private migration/store configuration and integration coverage; edge routes/authenticates without a business database. One identity scaffold must not stand in for all seven working owners.
- [ ] **Contracts before consumers:** concrete owner OpenAPI/JSON Schema, allowlisted action/MFA catalog, typed fixtures and generated Go/web clients precede dependent handlers/FE integrations. Root generator/client registry changes have a designated writer. Narrow missing invoice-issue, handover, registration, calculation/servicing and wholesale-entry contracts gate only their consumers.
- [ ] **Auth/provisioning negatives:** bootstrap, cookie/CSRF, single-use MFA/recovery, live permission/branch checks, service identity/header stripping and owner-party denial tests precede admitted integrations. Provider atomic rollback covers duplicate login/email/registration and invalid confirmation; secret-safe retry/receipts never leak/reset credentials. Empty provider workspace is not blocked by financial product policy; disputed recovery/security release remains explicit.
- [ ] **Shared-file serialization:** root Go/npm manifests and lockfiles, Compose, migration templates, schema tooling, shared web packages and central tests/config have explicit file ownership plus dependency ordering wherever writes overlap; claimed parallel lanes do not hide collisions. Runtime remains ≤ three workers/one browser-heavy QA.
- [ ] **Receipt variants:** known-VIN receipt is one atomic batch+units+placements+capacity command, not unidentified receipt followed by browser identification. Unidentified quantity occupies space without fake VINs; identification has zero occupied delta. Separate correction/move tasks carry scoped OD-06 gates and concurrency/rollback tests.
- [ ] **Branch saga:** identity coordinator and inventory prepare/commit/abort/status/detach are all represented. Tests cover fencing, pending visibility, retained failed branch, existing stock preservation, cancel-before-prepare tombstones and lost commit replies; no timeout release or abort after durable commit.
- [ ] **Shared reservation/finalization:** one inventory implementation serves commerce and retail; caller process tasks wait on its exact contracts. Include atomic sets, cross-owner race, exact-holder cancellation/tombstones, no TTL, physical-finalize-before-caller-completion and crash tests. Wholesale accepted-order consumer may use B-26 **or** B-27 contract, not an unnecessary all-of policy barrier.
- [ ] **Submission admission:** retail acquire/consume/release/snapshot/eligibility fence and both application-owner coordinators are wired and tested. Provider visibility waits consumed receipt; cancellation cannot undo commit/consume; delivery races share the guard. Insurance company+sale uniqueness remains; finance permanent one-active-application uniqueness is not invented.
- [ ] **Immutable clean files:** staging/finalized storage, exact-generation scanner, owner authorization, binding and authenticated downloads form a complete dependency chain. Overwrite-A-with-B, outage, foreign/draft access and safety-revocation tests must be assigned; clean is never business acceptance. Synthetic adapters do not silently become production scanner/storage policy.
- [ ] **Narrow policy/readiness:** approved mechanics, contract fixtures and existing-state FE remain separately buildable from live-data, calculation-policy and missing-state gates. OD-01 does not block finance review/document exchange; OD-08 does not block underwriting. OD-09/10 gate applicable money/snapshot commands, not every backend task. Cash contract/payment/delivery tasks must not depend on own-installment calculation or insurer progression.
- [ ] **Visual and execution evidence:** FE tasks carry exact M-ID/HTML entry/source/state refs; missing login/MFA, pending/stale/permission/scan/RFQ/logistics and locale states require captured or confirmed supplements, not nearby mock references or Figma. Distinguish planning `todo` from executable readiness: Git root+initial commit, exact version lock and task-local gates remain unmet until evidenced; mock tests are not application QA.

Audit output should cite task IDs and precise dependency/acceptance gaps only; do not reopen the approved architecture or infer answers to unresolved policies.
